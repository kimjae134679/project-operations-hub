# 영상다운로더 · 휴대폰에서 주소부터 저장 파일까지

## 설치와 사용

1. Galaxy S22에는 검증 후 제공되는 `dist/VideoDownloader-1.0.0-arm64-v8a.apk`를 설치합니다. `armeabi-v7a`는 오래된 32비트 기기용입니다.
2. 앱에서 **링크 추가**를 누릅니다. 직접 입력하거나 여러 주소를 줄을 나눠 붙여 넣습니다. 다른 앱의 공유 메뉴에서 영상다운로더를 선택해도 됩니다.
3. 기본 목록 또는 **새 목록**에 추가합니다. 목록에만 저장하거나 즉시 다운로드를 시작합니다.
4. **다운로드** 탭에서 전체 진행과 실패를 확인합니다. 알림에서도 일시정지할 수 있습니다.
5. 완료 항목의 **파일 열기**를 누릅니다. 파일은 휴대폰 **다운로드 → VideoDownloader**에 있습니다. 재생목록은 상세에서 개별 파일을 열거나 공유합니다.

일반 다운로드가 실패하면 상세의 **브라우저에서 찾기**를 누릅니다. 필요하면 로그인하고 영상을 직접 재생합니다. **찾은 미디어**에서 저장할 스트림을 선택하거나 **원래 주소 재시도**를 누릅니다. 사이트가 재생에 필요한 원본을 제공하지 않으면 저장되지 않을 수 있습니다.

설정에서 TXT/JSON 목록을 가져오거나 JSON으로 백업하고, 테마와 엔진 업데이트를 관리합니다. 일시정지·실패 항목은 이어받기/재시도로 다시 시도합니다. 일부 완료 항목은 이미 저장한 파일을 유지하며 남은 항목을 재시도합니다. 앱 강제 종료 후 자동 실행을 가장하지 않으며 앱을 열고 이어받기를 누릅니다.

## 자료 위치와 역할

| 위치 | 용도·행동 |
|---|---|
| `dist/*.apk` | 휴대폰 설치파일. 검증이 모두 끝난 뒤 생성·공유됩니다. |
| `dist/qa/RESULT.txt`, `native.txt` | 실제 빌드·검증 결과를 읽습니다. 파일 존재와 모든 사이트 성공은 다릅니다. |
| `dist/qa/screenshots`, `android.png` | 화면 QA와 에뮬레이터의 실제 화면을 확인합니다. |
| 휴대폰 `다운로드/VideoDownloader` | 저장된 영상·음원. 기존 파일은 덮어쓰지 않고 `_001` 이름으로 구분합니다. |
| 앱 내부 목록 | 링크·목록·진행·파일 위치. 설정의 내보내기로 사용자가 직접 백업합니다. |
| 앱 전용 `pending/항목ID` | 다운로드 중·이어받기용 임시 파일. 저장 완료 뒤 해당 임시 파일을 정리합니다. |
| 앱 내부 `cookies/` | 사용자가 앱 브라우저에서 로그인한 쿠키. 일반 목록 백업과 소통 기록에 넣지 않습니다. |
| `app/src/main/` | Android 다운로드 엔진·브라우저·화면 구현 원본. |
| `qa/`, `app/src/test/`, `app/src/debug/` | 자동 검사와 개발 검증 전용 계측 코드. |
| `_통합소통/보낼자료` | 본인 요청·실제 답변·검증·남은 일의 구조화 기록. |
| 기존 PC `D:\AI\video-downloader` | 이전 PC Python 다운로더·입력 링크·원본 다운로드 결과. Android 설치와 별개의 프로그램이며 이 작업에서 이동하지 않습니다. |

## 실제 작업·연결 상태

Android 작업 원본은 현재 ChatGPT 작업 폴더의 `VideoDownloaderAndroid`이며 동일 소스를 통합 GitHub의 `video-downloader-android-20261006` 전용 브랜치에 보존합니다. 로컬 작업 제한으로 D 드라이브에 새 Android 프로그램을 설치하지 않았습니다. 기본 D:\A_KJ\AI 정책의 예외 이유는 허용된 작업 폴더에서 구현하고 GitHub 빌드 환경에서 APK를 만드는 현재 권한 제한입니다. 바탕화면에는 저장하지 않습니다.

통합소통방의 N-0001~N-0009와 기존 프로젝트 안내를 읽었습니다. 본인 기록의 작성과 기존 PC 소통함에 대한 배포·중앙 앱 수집은 구분합니다. 기존 PC 소통 폴더에 대한 쓰기·자동 수집은 확인되지 않았습니다. 실제 휴대폰 설치/사용과 모든 외부 사이트 성공은 자동 QA와 별도입니다.
