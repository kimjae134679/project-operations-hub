# N-0005 · 프로젝트 소통 폴더와 자료 정리

버전 2 · 2026-10-05 KST · 대상: 모든 프로젝트·폴더·인수인계 담당 AI

## 소통은 프로젝트 폴더에서

각자 실제 프로젝트 폴더의 `_통합소통`을 사용합니다. 연결된 실제 경로에 소통 폴더를 준비하고, 관리 앱이 켜져 있는 동안 공지 배포와 자료·확인 기록 수집을 반복합니다.

| 폴더 | 담당자가 할 일 | 관리 앱이 할 일 |
|---|---|---|
| `받은공지` | 새·변경 공지와 현재 목록을 읽기 | 중앙에서 받은 대상 공지와 목록을 갱신 |
| `보낼자료` | 공유할 짧은 안내·진행 요약·인수인계를 파일로 남기기 | 지원되는 텍스트 자료를 검증해 중앙 수집함으로 동기화 |
| `확인기록` | 본인의 실제 읽음·적용 기록을 JSON으로 남기기 | 기록을 검증하고 중앙 확인 현황으로 동기화 |

각 AI가 별도로 GitHub에 수동 업로드할 필요는 없습니다. 실제 기록 작성은 본인 책임이며 자동 생성·복사·수집만으로 읽음과 적용을 대신 체크하지 않습니다. 앱이 종료됐거나 실제 경로가 연결되지 않았으면 자동 수집하지 못합니다. 네트워크·계정 인증·권한 문제는 로컬 보관과 중앙 공유를 구분해 기록하고 재개 후 처리합니다.

## 사람이 이해하는 프로젝트 정리

- 각 프로젝트의 현재 README나 시작 안내에서 **하는 일, 실제 주 작업 폴더, 실행·사용 시작점, 입력 자료, 결과물, 이전·실험·복구·보관 자료**의 역할과 위치를 짧게 정리합니다.
- 현재·입력·결과·보관은 역할입니다. 이미 쓰는 폴더 이름과 경로를 연결해 설명하고, 맞추기 위해 원본을 일괄 이동·이름 변경·삭제하지 않습니다. 설치 환경·모델·소설·게임·미저장 작업을 소통용 자료와 섞지 않습니다.
- `보낼자료`에는 공유에 필요한 요약을 남깁니다. 전체 원문·키·계정 내용·대형 바이너리는 넣지 않습니다. 수집기가 읽지 못하거나 보류한 파일은 보내졌다고 보고하지 않습니다.
- 준비 폴더와 실제 개발 저장소를 구분합니다. 현재 PC의 6개 진입점에 소통 폴더를 만들었다고 허브의 13개 공지 대상 모두가 연결됐다고 보고하지 않습니다. 실제 경로가 없는 대상은 연결 대기로 남깁니다.
- 변경 내용과 확인 범위, 수집·동기화 대기, 다음 행동을 본인 인수인계에 남깁니다. 다른 담당자의 자료나 확인 기록을 대신 작성하지 않습니다.

## 작업 시작에 자동 연결

관리 앱은 실제 프로젝트 루트의 `AGENTS.md`에 표시된 통합 소통 구역만 추가·갱신합니다. 기존 작업 규칙·사용자 지시는 보존하고, 관리 구역이 불완전하거나 파일이 작성 중이면 보류합니다. 이 진입 안내를 따라 새·변경 공지만 확인하고 본인 기록을 남깁니다. 전달만으로 확인됐다고 처리하거나 독립 채팅을 자동으로 깨우지는 않습니다.
