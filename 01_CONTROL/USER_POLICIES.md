# User Policies

## 적용 범위
- 이 정책은 현재 ChatGPT 프로젝트에서 허브를 통해 수행하는 작업에만 적용합니다.
- 다른 ChatGPT Project나 독립 채팅의 전역 정책으로 자동 확장하지 않습니다.
- 실제 프로젝트 저장소의 현재 상태와 사용자 최신 지시가 오래된 허브 기록보다 우선합니다.


## 공지 확인과 전달
- 허브에 연결되어 작업하는 모든 담당 AI는 시작·재개·인수인계 시 최신 공지 목록을 확인합니다. 새·변경 공지는 실제로 읽고 본인 프로젝트·AI·세션·공지 버전·해시·확인 시각·적용 상태를 기록합니다.
- 공지 원본은 `04_COMMUNICATION/announcements/`입니다. 담당자는 프로젝트의 `_통합소통/받은공지`를 읽고 본인 JSON을 `확인기록`, 공유할 요약을 `보낼자료`에 남깁니다. 관리 앱이 수집해 중앙 `receipts/`와 자료 수집함에 동기화합니다. 담당자별 GitHub 수동 업로드를 완료 조건으로 강제하지 않습니다. 다른 담당자를 대신 체크하지 않습니다.
- 공지 내용이 바뀌면 재확인합니다. 읽음과 적용 완료를 구분하고 적용 대기·해당 없음·막힘에는 구체적 설명을 남깁니다.
- 폴더 생성·공지 배포·로컬 작성·앱 수집·중앙 공유·실제 읽음·적용을 구분합니다. 앱은 켜진 동안 연결된 실제 경로를 반복 확인하며 종료 중에는 수집하지 않습니다. 인증·권한·오프라인·미연결 경로는 대기로 남기고 재개 후 처리합니다. 중앙 현황은 실제 동기화한 기록만 집계하며 모든 독립 채팅을 감시한 결과로 취급하지 않습니다.
- 현재 PC의 6개 진입점과 허브의 13개 공지 대상을 섞지 않습니다. 대상별 실제 경로·ID 연결을 확인하고 없는 경로와 빈 준비 폴더를 실제 개발 저장소로 추정하지 않습니다.
- 각 담당자는 프로젝트의 현재 README나 시작 안내에 용도·실제 작업·실행 진입점·입력·결과·보관 역할과 소통 폴더를 연결합니다. 기존 폴더명을 역할로 설명하며 정리를 이유로 원본·실행기·모델·데이터를 임의 이동·삭제하지 않습니다.
- 연결된 프로젝트별 진입 안내·공용방·우편함에서 공지를 필독으로 연결합니다. 독립 채팅을 자동으로 깨우거나 계정 전체에 정책을 주입했다고 주장하지 않습니다. 현재 사용자 지시·실제 프로젝트 규칙·수정 권한이 우선합니다.

## 작업 방식
- 요청한 일은 끝까지 처리하고 부분 구현을 완료라고 부르지 않습니다.
- Known-Good를 보호하고 broad rewrite보다 작은 검증된 수정을 우선합니다.
- 기존 코드·플랫폼 기본 기능·이미 설치된 의존성을 먼저 검토합니다.
- placeholder, fake data, fake success로 실패를 숨기지 않습니다.
- 위험이 작고 되돌릴 수 있는 애매함은 합리적 기본값으로 진행합니다.

## 탐색과 보고
- 요청과 직접 관련된 진입 문서·최신 상태·필요 파일부터 읽습니다.
- 긴 스레드나 저장소 전체를 매번 처음부터 읽지 않습니다.
- 과거 기록은 검색으로 범위를 좁힌 뒤 필요한 부분만 확인합니다.
- 같은 자료를 이유 없이 반복 조회하지 않습니다.
- 사용자 보고는 결론, 근거, 변경, 검증, 남은 문제를 중심으로 간결하게 작성합니다.

## 도구/플러그인 선택
- 도구 활용 추천은 서브에이전트에 한정하지 않습니다. 작업 목적에 맞춰 연결된 Plugin, CLI, Skill, 공식 문서 검색, 코드 검사기, 화면 검증, 배치 처리, Jev를 비교합니다.
- 과거 조사·설치 이력은 참고입니다. 과거 카탈로그의 항목을 강제하지 않으며, 현재 공식 근거와 사용자 환경에서 더 좋은 최신 대안이 있으면 열린 비교를 합니다.
- 최신 사용자 지시는 필요한 서브에이전트·병렬 분업과 Jev 사용을 허용합니다. 어떤 도구도 매번 사용하거나 전체 프로젝트에 자동 활성화할 의무는 없습니다.
- 도구 사용 허가는 추가 결제, 카드 등록, 유료 전환의 허가가 아닙니다. 기존 무료·비용 정책을 계속 적용합니다.
- 상태는 `문서 확인 / 설치 확인 / 현재 연결 / 기능 실행 검증 / 사용자 흐름 완료`를 구분해 근거·날짜·실행 환경과 함께 기록합니다.
- 토큰·품질·지연 비용을 함께 비교합니다. 작은 작업의 과도한 분업, 불필요한 MCP/Skill 전체 로딩, 반복 검색, 지나치게 긴 로그·응답, 검증 없는 저가 모델 반복 재시도를 피합니다.
- 작업별 추천과 제한은 `03_KNOWLEDGE/CANDIDATE_CATALOG/TOOL_SELECTION_PLAYBOOK.md`에 정리하고 사용자 요약 `000_사용자용/10_도구_활용_추천.md`와 함께 유지합니다.
- 새 AI 도구·Plugin·Skill·MCP·CLI·Agent 후보는 **AI가 사용자 개입 없이 실제 기능까지 다룰 수 있는지**를 별도 항목으로 기록합니다.
- `설치 가능`과 `AI 단독 운용 가능`은 다른 상태로 봅니다. 설치는 AI가 해도 매번 GUI 조작·시각 판단·로그인 확인이 필요하면 단독 운용으로 분류하지 않습니다.
- 비용 상태는 `무료/오픈소스`, `기간 제한 없는 무료 플랜`, `기존 요금제 포함`, `무료체험`, `유료`, `미확인`으로 구분합니다.
- 오픈소스 앱 자체가 무료여도 외부 API·모델·클라우드 실행비용이 들 수 있으면 프로그램 비용과 외부 실행비용을 분리해서 기록합니다.
- **추가 결제가 필요한 유료 도구는 기본 후보/추천/설치 대상에서 제외합니다.** 사용자가 명시적으로 요청했을 때만 검토합니다.
- **기간 제한 무료체험도 기본적으로 피합니다.** 무료체험만 가능한 도구는 특별한 이유가 없으면 설치·연결하지 않습니다.
- 우선순위는 대체로 `무료/오픈소스 → 기간 제한 없는 무료 플랜 → 기존 요금제 포함 → 무료체험 → 유료` 순입니다.
- 카드 등록, 자동결제 전환, 크레딧 소진 후 과금 가능성이 있으면 무료처럼 취급하지 않고 별도 경고합니다.
- 가격/무료 여부가 확인되지 않은 도구는 추측해서 무료라고 쓰지 않고 `미확인`으로 둡니다.

## 병렬 작업과 사용량
- 단순 수정은 담당자 한 명으로 처리할 수 있습니다. 독립적인 코드 탐색·재현·공식 문서 확인·검토는 필요한 범위만 병렬화합니다.
- 시작값은 하위 작업 2~3개로 두되 작업 규모·의존성·사용 한도·측정 결과에 따라 조정합니다. 수가 많다는 이유만으로 품질이나 효율이 높다고 판단하지 않습니다.
- 병렬 수정에는 파일 소유 범위 또는 별도 worktree를 지정하고 통합 담당자를 둡니다. 변경 대상과 순서를 공유하지 않은 동시 편집을 피합니다.
- 작업 전달은 목표·필수 맥락·경로·수정 범위·완료 조건·반환 형식으로 제한합니다. 전체 채팅과 긴 원본 로그를 모든 작업자에게 반복 전달하지 않습니다.
- 구현 diff가 생긴 뒤 검토를 시작합니다. 검토자는 구현 결과와 필요한 근거를 확인하며 구현자의 완료 선언만 받아 성공 처리하지 않습니다.
- 전체 실행의 사용량·시간·성공률·재시도를 비교합니다. 주 대화가 짧아졌다고 총 토큰이 절약됐다고 단정하지 않습니다. 모델·캐시·요금제에 따라 토큰 수, 실제 과금, 사용 한도는 서로 다를 수 있습니다.
- Jev는 모델 선택 경로입니다. 작업 발견·큐·실행·검증·재시도·결과 전달은 별도 실행기 책임으로 유지합니다. API 키 존재나 CLI 로그인만으로 왕복 실행 성공을 선언하지 않습니다.

## UI/UX
- `현재 상태 → 지금 할 행동 → 결과 → 상세` 순서를 우선합니다.
- 대표 CTA를 명확히 하고 중복 버튼을 줄입니다.
- 사람용 화면에는 한글 이름과 확인된 용도·행동을 보여줍니다. 내부 ID·파일명·명령·영어 상태값을 그대로 일반 설명으로 쓰지 않고 필요한 진단 정보는 상세에 둡니다.
- 같은 프로젝트의 현재 작업·실험·복구·보관 폴더를 구분하고 보관 자료는 기본 접힘으로 둡니다. APK 위치 보기, PC 프로그램 실행, 웹 화면 열기를 같은 행동으로 표시하지 않습니다.
- 설명은 무엇인지와 눌렀을 때 하는 일을 이해하는 데 필요한 만큼만 적습니다. 반복 배너·의미 없는 상태·중복 설명을 제거하고 실제 화면에서 한글·작은 창·핵심 버튼을 확인합니다.
- 새 폴더의 존재만으로 용도·최신 버전·정상 작동을 추측하지 않습니다. 현재 README·인수인계·실제 파일을 확인하고 조사 날짜와 근거를 남깁니다.
- 다음 AI도 `01_CONTROL/PROJECT_PRESENTATION_RULES.md`를 적용합니다. 프로젝트 설명·연결 정보를 바꾸면 `project.catalog.json`과 `000_사용자용/11_프로젝트와_폴더_안내.md`를 함께 맞춥니다.
- 모바일이라고 중요한 기능을 삭제하지 않습니다.
- 눈에 바로 보이는 단순 성공 토스트를 남발하지 않습니다.
- 위험한 삭제/덮어쓰기는 명시적으로 선택된 대상에만 적용합니다.

## 데이터/복구
- Unknown과 실제 0을 구분합니다.
- 설치파일과 사용자 데이터를 분리합니다.
- 배포된 ID/key/storage name을 호환성 계약처럼 다룹니다.
- migration 전 백업/복원 경로를 확보합니다.
- 핵심에 서버가 필요 없으면 local-first를 우선 검토합니다.

## 빌드/검증
- CI, build, install, 실사용, 실기기 PASS를 구분합니다.
- 실제 전달 파일과 검증 파일이 같아야 합니다.
- 변경 영향에 필요한 검증만 수행합니다.
- 중요한 산출물은 필요하면 SHA-256을 남깁니다.

## Windows/원격
- UTF-8, 한글 IME, 공백/한글 경로를 관련 변경에서 확인합니다.
- Remote Desktop이 online이면 작업 종료를 이유로 연결 서비스를 끄지 않습니다.
- child process 정리와 connection service 종료를 구분합니다.
- 실제 PC가 offline이면 local verification을 했다고 주장하지 않습니다.
- **Remote Desktop Commander/데스크톱 원격을 사용한 회차는 임시 빌드 산출물, 중간 APK/ZIP/IDSIG, cache, probe, `__pycache__`, 불필요 로그 등 그 작업이 만든 찌꺼기를 종료 전에 정리하는 것까지 완료 조건입니다.** 최종 산출물과 재현에 필요한 소스/스크립트는 남기고, 사용자 데이터·Known-Good·원본/reference 자료는 임의로 삭제하지 않습니다.

## AI 설치/작업 위치
- 최신 사용자 지시는 D드라이브의 AI 폴더 사용입니다. 2026-10-05 PC에서 관찰한 관리 루트 `D:\A_KJ\AI`를 새 AI 프로그램·도구·실험 프로젝트의 기본값으로 사용합니다. 이 값은 당시 관찰에 근거하며 사용자 변경 지시나 실제 PC 이동이 있으면 다시 확인합니다.
- 새 항목은 루트에 흩어놓지 않고 `Applications`, `Installers`, `Scripts`, `Launchers`, `Projects`, `Workspace`, `External`처럼 역할별 폴더에 정리합니다.
- 패키지 매니저나 공식 업데이터가 기본 위치를 요구하거나 이동 시 업데이트/런타임이 깨질 가능성이 있으면 기본 설치 위치를 유지할 수 있습니다.
- 기본 위치를 유지한 예외는 실제 경로와 이유를 설치 레지스트리/인수인계에 기록합니다.
- 기존 안정 프로젝트를 이유 없이 대규모 이동하지 않습니다. 새 AI 작업부터 새 루트를 기본값으로 쓰고, 단순·안전하게 옮길 수 있는 기존 AI 설치물은 정리해 옮깁니다.
- 모든 프로젝트 인수인계에는 프로그램/도구/작업 폴더의 실제 위치와 `D:\A_KJ\AI` 기본 위치 정책 준수 여부·예외 이유를 적습니다. 정책상 기본 경로를 실제 설치·실행 위치로 대신 적지 않습니다.

## 명령·답변·작업 기록

- 허브에 연결된 AI는 받은 지시의 주요 요구·제약·출처·실제 수신 시각을 작업 시작에 기록하고 진행·완료·중단 때 실제 답변 요약·한 일·검증·남은 일·막힘을 갱신합니다. 원문 전체나 비밀값은 남기지 않습니다.
- 공식 단일 원본은 `05_TEMPLATES/TASK_EXCHANGE.schema.json`의 task_exchange JSON입니다. 사용자용 설명은 같은 원본에서 생성하며 별도 Markdown 복제 원본을 관리하지 않습니다. 사용법은 `05_TEMPLATES/TASK_EXCHANGE.md`입니다.
- 실제 `_통합소통/보낼자료`에 도우미 record로 본인 기록을 작성합니다. 동일 projectId·actorId·recordId의 revision을 올리고 이전 버전을 보존합니다. 새 지시는 새 ID를 사용하고 대체 관계를 남깁니다.
