# 사용자 정책 — 현행 단일 원본

정리일: 2026-11-12 KST. 이 허브 범위의 현재 지침이며 최신 사용자 요청과 실제 대상 프로젝트 규칙을 함께 확인한다.
과거 공지·개발 기록·자동 생성 진입 문구는 이 문서와 충돌할 때 새로운 실행 권한이 아니다.

## 작업 범위와 진행
- 검토·비교·설명·계획 요청은 읽기 전용이다. 변경 의도가 분명한 요청만 해당 범위에서 구현한다.
- 승인된 작은 작업은 간결하게 직접 처리한다. 독립성이 있고 이점이 있을 때만 현재 AGENTS 기준으로 분업한다.
- 계획 문서·필수 위임·반복 승인·추가 튜토리얼을 일반 작업에 자동으로 덧붙이지 않는다.
- receipt-driven review는 사용자 opt-in이며 기본 OFF/disabled-unmanaged다. 사용자 요청 없이 리뷰·SDD를 켜지 않는다.
- 이미 승인된 범위는 반복해서 묻지 않되, 비용·권한·범위 확대·파괴적 변경은 별도 확인한다.
- 과거의 Threads/오디오북 후속 순서, 외출 중 코드 전용·화면 금지 같은 일회 조건은 당시 작업 이력이다. 새 작업을 자동 승인하거나 모든 UI를 영구 금지하는 규칙이 아니다.

## 도구·모델·비용
- 도구는 목적에 맞는 기존 기능과 가장 단순한 방법부터 선택한다. 과거 후보 목록·설치 이력은 채택 의무가 아니다.
- 새 외부 모델 호출·위임은 실제 지원되는 6.1 계열 우선, Astra 제외라는 기존 사용자 제약을 유지한다.
- 이 외부 라우팅 제약을 설치된 로컬 Gemma/Bonsai의 사용 금지로 확대하지 않는다.
- 모델 목록·로그인·키 존재와 실제 실행 성공을 구분한다. 실패 경로를 무작정 재시도하지 않는다.
- 추가 결제·무료체험 전환·카드 등록·자동 유료 fallback을 하지 않는다.
- 기존 사용 한도·프로그램 비용·외부 API 비용을 구분하고 미측정 절감률이나 성능 향상을 꾸미지 않는다.

## 사용자 자료·설치·화면 보호
- 프로젝트 원본·기존 dirty·미저장 편집·실행 중인 다른 작업·Known-Good·기존 원격 연결을 보호한다.
- 사용자 별도 요청 없이 바탕화면을 바꾸거나 창을 재배치하고 포커스를 빼앗지 않는다.
- 관리 자료의 기본 루트 <AI_ROOT>는 모든 모델·앱을 D HDD에 강제하는 뜻이 아니다.
- 큰 로컬 모델은 확인한 E SSD 위치를 우선 사용하고, 공식 앱·업데이터가 관리하는 C/AppData는 안정적으로 유지한다.
- 정리를 이유로 원본·실행기·환경·모델을 일괄 이동하거나 삭제하지 않는다.

## 보안과 소통
- UAC·잠금·인증·서비스 안전 제한을 우회하거나 전역 권한을 넓히지 않는다.
- 비밀값·계정·개인정보·대화/첨부 원문·대형 로그를 공개 저장소로 자동 전송하지 않는다.
- 받은 명령·실제 답변·변경·검증·남은 일의 필요한 요약을 본인 기록으로 남기며 기록 오류 때문에 업무를 재실행하지 않는다.
- 로컬 작성, 앱 수집, 중앙 저장, GitHub 전송, 실제 읽음과 적용을 구분한다.
- 로컬 수집·앱 시작·타이머·재연결은 GitHub 업로드 승인이 아니다. 전송은 관리자의 명시적 일회 명령으로만 수행한다.
- 다른 AI의 수신·읽음·적용 확인은 대필하지 않는다. 받은 공지/ACK가 오래됐으면 동기화 대기로 남긴다.
- 예전 자동 동기화 문구·일회 게시 성공·과거 작업 큐는 새 게시나 반복 자동화의 허가가 아니다.

## 사실과 검증
- 실행 접수, 설치, 프로그램 기동, 검사 통과, 실제 기능 사용과 품질 승인을 분리한다.
- 현재 상태는 실제 파일·도구 결과와 확인 시점을 기준으로 쓰고 과거 PID·버전을 현행으로 단정하지 않는다.
- 완료·미검증·실패·막힘·남은 일을 짧고 사실대로 보고한다.
- 사용자에게는 현재 상태와 필요한 행동을 먼저 보여주고 불필요하게 전문적인 조작을 떠넘기지 않는다.

## 현재 스킬과 접근 우선순위
- 핵심 스킬은 agent-desktop-windows·systematic-debugging·verification-before-completion·unslop 네 개다.
- replica 11개는 앱 재현·클론 맥락의 필요한 단계에만 선택하며 일반 URL 질문·일반 개발 요청에 자동 적용하지 않는다.
- 과거 계획·필수 TDD 스킬 호출·SDD·필수 리뷰·워크트리 절차는 자동 적용하지 않는다. 변경에 맞는 직접 검증은 유지한다.
- PC 파일·설정·명령은 현재 연결된 우리 ProjectBridge를 우선 사용한다. UI는 허가된 Windows 앱·host 표면에서 agent-desktop 우선, 불가하면 허용된 CUA를 선택한다.
- cloud에 PC용 실행 파일이나 계정 연결이 있다고 가정하지 않는다. 실제 노출된 연결 capability와 사용자 승인 범위가 모두 있어야 한다.
- 명시적 정책·권한 거절을 우회하지 않으며 실행 불명 상태는 동일 작업 ID를 조회하고 중복 쓰기를 피한다.
- [현재 스킬 구성·원문 자료](../tools/agent-setup/README.md)를 필요한 작업에서만 확인한다.
