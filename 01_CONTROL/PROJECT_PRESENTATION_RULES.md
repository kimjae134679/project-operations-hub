# 프로젝트를 사람에게 보여주는 기준

적용: 이 허브의 관제 화면·프로젝트 목록·관련 폴더 안내·사용자용 인수인계. 사용자 최신 지시 **2026-10-05 KST**를 반영합니다. 다른 AI가 이어받을 때도 이 기준을 적용하며 실제 프로젝트의 현재 상태는 해당 저장소와 PC에서 확인합니다.

## 이름·설명·행동

- 일반 화면에는 사람이 알아보는 한글 이름, 하는 일, 지금 할 행동을 보여줍니다. 내부 ID, 파일명, 환경변수, 명령, 영어 상태값을 그대로 사용자 이름·설명·버튼으로 쓰지 않습니다. 필요한 실제 경로·원래 상태값은 상세 정보나 진단 기록에서 확인할 수 있게 둡니다.
- 프로젝트 이름은 무엇을 만드는지, 프로그램 이름은 무엇을 할 수 있는지 설명합니다. 폴더의 기술 이름만으로 용도를 확정하지 않습니다.
- 설명은 선택에 필요한 차이만 적습니다. 실행 도구인지, 설치파일인지, 입력·결과·개발·복구 자료인지와 누르면 무엇이 열리는지를 알려줍니다. 모든 항목에 같은 등록 설명·주의 문장·성공 문구를 반복하지 않습니다.
- 대표 행동은 대상과 일치해야 합니다. PC 프로그램은 실행, 웹 화면은 화면 열기, Android APK는 휴대폰 설치파일 위치 보기, 생성 음성은 결과 폴더 보기처럼 구분합니다. 폴더를 열어놓고 프로그램 실행 성공이라고 보고하지 않습니다.
- 목적을 확인하지 못한 항목은 용도 미확인으로 둡니다. 빈 준비 폴더·보관 자료·실행기가 연결되지 않은 개발 폴더에 실행 가능한 프로그램처럼 버튼을 붙이지 않습니다.

`project.catalog.json`에서는 `name`을 사람용 표시 이름으로 사용합니다. `description`, `roleLabel`, `kindLabel`, `openActionLabel`, `actionLabel`에는 확인된 용도와 행동을 적고, `id`·`path`·`commands`에는 내부 연결 정보를 둡니다. 화면 필드가 추가돼도 이 구분을 유지합니다.

## 같은 프로젝트의 여러 폴더

- 주작업 폴더를 하나의 프로젝트 진입점으로 두고, 같은 프로젝트의 실험 사본·복구 자료·이전 개발본·설치 위치는 `relatedFolders`로 연결합니다. 의미 없이 독립 프로젝트와 프로그램 수를 늘리지 않습니다.
- 관련 폴더에는 주작업·과거 테스트·복구·보관·설치 중 실제 확인된 역할을 적습니다. 역할을 모르면 추측하지 않습니다. 보관 자료는 기본 접힘으로 두고 주작업과 쉽게 구별합니다.
- 관리 기본 루트와 프로젝트의 실제 위치는 별개입니다. 오디오북의 실제 작업 위치 `D:\AI\VoiceAudiobook`처럼 기존 경로를 쓰는 프로젝트는 외부 폴더로 연결하고, 목록 정리를 이유로 원본을 이동하지 않습니다.
- 자동 발견은 존재 확인입니다. 새 폴더의 목적·최신 버전·실행 명령까지 파일명으로 추론하지 않습니다. 현재 README·인수인계·실제 파일을 필요한 만큼 확인한 다음 사람용 이름과 설명을 등록합니다.

## 상태와 근거

| 확인한 사실 | 화면·인수인계에 적을 수 있는 범위 |
|---|---|
| 파일·폴더 존재 | 위치 확인됨. 설치·실행·정상 작동을 뜻하지 않음 |
| 실행파일과 명령 연결 확인 | 시작 가능 여부 확인. 실제 실행 성공과 별개 |
| 실제 프로세스 실행 | 실행 중. 외부 연결·전체 기능 완료와 별개 |
| 실제 서비스 응답·연결 확인 | 확인한 서비스 연결됨. 프로젝트 작업 완료와 별개 |
| 해당 작업의 결과 확인 | 확인한 작업 완료. 검증하지 않은 기능·기기까지 확대하지 않음 |
| 사용자의 특정 버전 정상 작동 확인 | 해당 버전·확인 범위의 완료본. 새 작업본에 자동 승계하지 않음 |

사용자 화면의 상태는 짧은 한글로 표시하고, 종료 코드·원래 영어 상태·상세 로그는 필요할 때 펼칩니다. 실패 안내는 무엇이 실패했는지와 다음 행동을 알려줍니다. 의미 없는 기술 상태나 반복 배너로 화면을 채우지 않습니다.

## 이어받을 때 확인할 현재 구성

2026-10-05 KST에 확인한 카탈로그는 멀티의 신(별도 서버 화면 포함), 무직전생 오디오북, 영상·음원 저장, 전체 프로젝트 관리, 주식 자동매매 준비 폴더, 청약 도구 준비 폴더의 6개 진입점입니다. 다음 사실을 혼동하지 않습니다.

- 최근 작업본과 사용자 확인 완료본 0.23.4를 구분합니다. 현재 작업본은 해당 저장소와 실제 설치파일에서 확인합니다. APK는 휴대폰 설치파일이며 PC 게임 실행파일이 아닙니다.
- `PhoneLOL\APK`는 이전 서버 코드가 들어 있는 폴더입니다. 이름만 보고 휴대폰 설치파일로 분류하지 않습니다. 현재 운영 서버는 별도 `C:\Users\user\Documents\MultiGod\PhoneLOL_LocalRuntime`이며 공지 대상 `PhoneLOL-Server`로 구분합니다.
- `PhoneLoL_02-CloudTest`의 옛 안내를 현재 개발본 기준으로 적용하지 않습니다. `PhoneLOL-Recovery-v11511`은 복구 자료입니다.
- `txt_무직전생`은 코드 보관본입니다. 실제 오디오북 제작·생성 결과는 `D:\AI\VoiceAudiobook`에서 확인합니다.
- 주식·청약 폴더는 조사 당시 비어 있었습니다. 실제 프로그램이 생기기 전에는 실행 기능이 있다고 표시하지 않습니다.
- 초기 조사에서 표준 Unity 경로는 없었지만, 실제 설치는 `C:\Program Files_My\A_3D\Unity_Hub\Unity_Editor\6000.3.14f1\Editor\Unity.exe`에 있습니다. 기존 `Automation/OpenUnity.ps1`의 같은 프로젝트 중복 방지와 열기 연결을 확인했습니다. 파일 존재·연결 구성과 실제 편집기 열기 성공은 구분합니다. 관리 앱 종료로 편집기의 미저장 작업을 강제 종료하지 않습니다.

## 갱신과 UI 검증

카탈로그의 `evidencePath`·`checkedAt`는 조사 출처와 당시 확인 날짜입니다. 카탈로그·이 문서·과거 탐색 결과는 참고이며 현재 상태를 대신하지 않습니다. 사용자가 새 정보를 주거나 경로·버전·실행기가 바뀌었으면 최신 README·인수인계·실제 존재와 동작을 다시 확인합니다. 새롭거나 더 좋은 연결·도구·디자인 방향도 열린 기준으로 비교합니다.

변경 후 실제 앱에서 일반 화면과 작은 창을 확인합니다. 한글 제목과 핵심 행동이 잘리는지, 선택한 프로젝트의 설명·대상이 맞는지, 실행과 위치 보기가 구별되는지, 보관 자료가 주작업을 가리지 않는지 확인합니다. 실제 실행하지 않은 앱·작업의 UI 시안이나 파일 존재만으로 사용 검증 완료를 선언하지 않습니다.

이 기준을 바꾸면 [사람용 폴더 안내](../000_사용자용/11_프로젝트와_폴더_안내.md)와 실제 카탈로그·화면 설명을 함께 맞춥니다. 비밀값·계정 내용·소설 원문을 사용자 안내나 인수인계에 복사하지 않습니다.

## 2026-10-06 디자인 선택과 테마

사용자가 추가 예시 2(레이어 사이드바), 6(펼치는 목록), 7(타일 작업실), 8(겹친 작업 카드)를 우선 선택했습니다. 1(폴더 선반)은 제외, 5(서류철)는 항목이 많아질 때의 사용성이 조건입니다. 프로젝트 이름을 계속 보여주는 검색 가능한 목록, 선택한 프로젝트의 겹친 면, 기능별 펼침과 작업 카드를 실제 WPF 앱에 적용합니다. 자동 카드 회전이나 메뉴를 열어야 기본 항목을 찾는 구조는 사용하지 않습니다.

색만 바꾸는 개편은 충분하지 않습니다. 레이어·깊이·선택·포커스와 짧은 전환을 함께 설계합니다. 밝은 화면을 기본으로 두고 사용자가 어두운 화면으로 전환할 수 있습니다. 배경·본문·설명·상태·버튼·선택·입력·드롭다운·이미 열린 공지와 보조 창을 함께 전환합니다. 작은 글자는 배경과 최소 4.5:1 대비를 확보하고, 실제 Windows 렌더링과 작은 창·휠을 검증합니다.

과거 링크와 시안은 참고이며 전체 최종 디자인 승인이나 현재 상태를 대신하지 않습니다. 이 작업은 프로젝트의 폴더·파일·카탈로그 연결을 이동하거나 변경하지 않습니다.
