# 통합관제 승인 작업 · 우선순위와 완료 기준

현재 사용자 직접 지시까지 반영한 작업 목록입니다(2026-10-07 KST). 기능 계획, 소스 구현, 검사 통과, 배포 준비, 운영 설치, 실제 사용 완료는 별개입니다. 이 문서는 완료표나 다른 담당자의 읽음 확인을 대신하지 않습니다. 최신 진행은 본인 task_exchange와 해당 프로젝트의 실제 상태를 확인합니다.

## 항상 적용할 제한

- 직접 화면을 보거나 스크린샷을 찍지 않고 마우스·키보드·사용 중인 창을 조작하지 않습니다. 사용자가 첨부한 정지 스샷은 참고할 수 있습니다. 코드·로그·검사와 실제 창 없는 메모리 렌더링으로 판단합니다.
- 바탕화면 파일·폴더·바로가기·창 배치를 건드리지 않습니다. 새 관리 자료는 D드라이브 AI 관리 폴더에 둡니다.
- 기존 원격 두 연결, Known-Good, 실행 중인 제작, 다른 담당자의 미커밋 변경을 보존합니다. 자유 shell 실행과 임의 PID 제어를 UI 편의 기능으로 추가하지 않습니다.
- Jev 로컬 사용 금지는 폐기됐습니다. 사용 허가는 설치·지원 모델·연결·실제 작업 성공 또는 추가 결제 허가를 뜻하지 않습니다. Astra, 결제·무료체험 전환, 계정 권한 변경, 원본 대량 삭제, 외부 게시, 플랫폼 승인/보호정책 우회는 제외합니다.
- 등록된 본인 소유 작업만 실행/중지합니다. 결정적인 상태 조회·수집·검사·기록은 모델 없이 처리합니다. 한도/지원 실패를 반복 호출하지 않습니다.
- 공지 배포·로컬 작성·수집·중앙 공유·본인 읽음·적용을 구분합니다. 다른 AI의 확인·답변을 대필하지 않습니다. receipt-driven review는 disabled/unmanaged입니다.

## P0 · 보호와 사실 확인 (다른 모든 작업의 선행조건)

1. 중복 실행 방지: 소유 작업 ID·프로세스·체크포인트부터 확인하고 이미 생성 중인 오디오북과 완료 단계는 재시작하지 않습니다.
2. 설치본/소스/중앙 main/프로젝트 원본을 구분합니다. 현재 실행 앱0.7과 새 소스0.9의 불일치를 감추지 않습니다.
3. 실패 원인을 근거로 찾고 원격/설정/Git dirty/미저장 작업을 보존합니다. 접근 거부나 정책 거절은 다른 도구로 우회하지 않습니다.

완료 기준: 모든 변경에 소유 범위와 근거가 있고, 기존 실행·파일을 손상하지 않았음을 확인합니다. 이 조건은 지속 적용입니다.

## P1 · 기존 통합앱 기능과 사용성 (소스 구현·코드 검증 완료, 활성화 대기)

## P2 · 운영 연결·기록·동기화

1. 통합소통 Git 반영 실패: 현재 clone에 Git lock이 남아 있고 실패 단계는 git add입니다. 당시 stderr/락 생성 주체는 아직 미확인입니다. 락을 임의 삭제하지 않고 단계·종료코드·정제된 진단이 보존되게 합니다. 수집 자료 보존과 중앙 공유 성공은 별개입니다.
2. ProjectBridge 운영 업데이트: 장기 프로세스의 실제 완료·실패·의존성 source 수정은 검사 통과했지만 config 쓰기 거부로 설치 실패 후 rollback됐습니다. 기존 원격은 유지하고 지원되는 설치 경로의 원인을 확인합니다. 동일 설치 재시도/ACL 변경/보호 우회는 하지 않습니다.
3. 두 원격 경로의 역할: 현재 작업용 연결과 복구용 연결을 구분하고 상태·실제 명령 왕복·오류를 표시합니다. 하나의 복구를 위해 다른 연결을 임의 종료하지 않습니다.
4. 명령/답변/작업 결과/checkpoint를 각 담당자 본인 기록으로 남기고 앱에서 로컬 작성/수집/중앙 공유 상태를 구분합니다. 자동 수집을 모든 채팅 상시 감시로 설명하지 않습니다.

완료 기준: 운영 버전과 실제 왕복/완료 결과 확인, 실패 진단·복구·기록 공유를 검증. 소스 검사만으로 운영 완료라고 하지 않습니다.

## P3 · 명령 하나로 이어지는 작업 체계와 비용 절감

- 승인된 계획의 작업 큐, 프로젝트/명령 주체별 독립 workspace, 의존성, 체크포인트, 완료 단계 재실행 방지, 소유권 잠금, 중단/안전 재개를 연결합니다.
- 오래 걸리는 자식 프로세스는 접수≠완료입니다. 결과 불명/실패/중단이 다음 의존 작업을 성공처럼 열지 않게 합니다.
- 고정 반복은 스크립트·상태 수집기로 처리하고 판단이 필요한 단위만 지원 확인된 비Astra 모델에 전달합니다. Jev는 옵션이며 꼭 필요한 도구는 아닙니다.
- 모델별 실제 지원·기존 사용 가능 한도·호출 성공·비용 조건을 확인하고, 등록된 작업 로그/결과 없이 Jev 진행률을 꾸미지 않습니다.
- 상시 판단·미리 예약된 다음 명령·모델 회복은 실제 지원되는 실행기에서 검증 후 연결합니다. 추가 요금/권한을 자동 승인하지 않습니다.

현재: 결정적 2단계 연속 실행과 동일 계획 재실행 시 attempts1은 확인했습니다. 전체 프로젝트 자율 판단·Jev 왕복·운영 장기 실행은 미완료입니다. 측정하지 않은 토큰 절감률은 쓰지 않습니다.

## P4 · 각 프로젝트 후속 작업 (기반 실제 검증 후)

1. 각 프로젝트 담당자에게 최신 공지를 실제로 읽고 본인 확인·적용 기록을 남기도록 전달합니다. 전달됨≠읽음이며 미응답/막힘은 목록에 남깁니다.
2. 인스타 수익화/Threads: 실제 프로젝트 README/AGENTS·미커밋 변경·사용자 평가를 먼저 확인하고 남은 편집/평가/프로그램 개선을 이어갑니다. 외부 게시/계정 연결/결제는 하지 않습니다.
3. 무직전생/VoiceAudiobook: 현재 production 실행 생존과 진행을 확인하고 기존 생성 작업을 중복 시작하지 않습니다. 실패/검토 단위와 사용자 승인 대기를 분리해 이어갑니다. 생성 완료≠청취·품질·외부 배포 승인입니다.
4. 나머지 진행 중인 프로그램: 실제 저장소와 담당자 원본 기록에서 남은 일·완료 기준을 확인한 뒤 독립 소유 작업으로 연결합니다. 허브 등록만으로 다른 프로젝트 수정 권한을 확대하지 않습니다.

## P5 · 후순위 정리

1. 실제 확인된 각 프로젝트 GitHub에 공지 확인·본인 기록·인수인계의 최소 규칙만 적용합니다. 기존 고유 규칙·미커밋 변경을 덮어쓰지 않습니다. 앞선 일반 업무가 완료된 뒤 수행합니다.
2. Obsidian: 공식 배포/지원 옵션을 확인하고 D HDD에서 작은 문서 중심 성능을 먼저 판단합니다. 프로그램·vault·설정/캐시의 C 쓰기 회피를 보장 못하거나 성능이 부적합하면 설치를 보류합니다. 바탕화면 바로가기·유료 Sync·계정 연결은 하지 않습니다.

## 다음 안전한 단위

P1의 전체현황/공지·댓글/내부읽기/테마 코드는 통합 코드 검사 218개와 스크립트 검사44개를 통과했고 source0.9.0 배포를 준비했습니다. 창을 만드는 기존 휠검사3개는 최신 사용자 금지에 따라 제외(미실행)했습니다. 다음에는 versioned 배포 파일·소스 대응을 검증하고 기존 창을 건드리지 않는 활성화 방법과 P2 막힘을 지원 경로로 확인합니다. 기존 사용창을 종료하거나 활성화하지 않고 source·검사·배포준비·활성화 대기를 정확히 기록합니다. 그 후 P2의 확인된 운영 막힘을 지원 경로로 처리합니다.
