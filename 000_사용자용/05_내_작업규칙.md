# 내가 정한 공통 작업 규칙

AI가 프로젝트를 작업할 때 지켜야 할 핵심만 사용자용으로 정리합니다.

## 작업 방식

- 요청한 일을 끝까지 처리하고 중간 단계만 해놓고 완료라고 하지 않습니다.
- 정상 동작하던 기준판을 보호하고, 큰 재작성보다 작은 검증된 수정을 우선합니다.
- 기존 코드와 이미 설치된 기능을 먼저 활용합니다.
- 가짜 성공, 임시 placeholder, fake data로 실패를 숨기지 않습니다.
- 위험이 작고 되돌릴 수 있으면 사소한 질문을 반복하기보다 합리적인 기본값으로 진행합니다.

## 새 AI 도구를 고를 때

- 단순히 설치 가능한지만 보지 않고 **AI가 실제 기능을 혼자 끝까지 다룰 수 있는지**도 따로 표시합니다.
- 설치는 AI가 해도 매번 내가 GUI를 조작하거나 결과를 선택해야 하면 `AI 단독 운용`으로 보지 않습니다.
- 비용은 `무료 / 무료 플랜 / 기존 요금제 포함 / 무료체험 / 유료 / 미확인`으로 나눕니다.
- **추가 결제가 필요한 유료 도구는 기본적으로 다루지 않습니다.** 내가 따로 요청할 때만 검토합니다.
- **기간 제한 무료체험도 웬만하면 사용하지 않습니다.** 무료체험만 가능한 도구는 특별한 이유가 없으면 설치·연결하지 않습니다.
- 우선순위는 `완전 무료·오픈소스 → 기간 제한 없는 무료 플랜 → 이미 쓰는 서비스에 포함 → 무료체험 → 유료` 순으로 봅니다.
- 카드 등록이나 무료기간 종료 후 자동결제가 붙는 것은 무료처럼 취급하지 않습니다.
- 가격이 확실하지 않으면 추측하지 않고 `미확인`으로 둡니다.

## 화면과 사용성

- `현재 상태 → 지금 할 행동 → 결과 → 상세` 순서로 이해하기 쉽게 만듭니다.
- 대표 버튼을 분명히 하고 같은 기능의 중복 버튼을 줄입니다.
- 모바일이라고 중요한 기능을 빼지 않습니다.
- 단순 성공 알림을 남발하지 않습니다.
- 삭제·덮어쓰기는 사용자가 명확히 고른 대상에만 적용합니다.

## 데이터와 복구

- 알 수 없는 값과 실제 0을 구분합니다.
- 프로그램 파일과 사용자 데이터를 분리합니다.
- 이미 배포된 ID·저장키·DB 구조는 호환성 계약처럼 다룹니다.
- 큰 변경 전에는 백업/복원 경로를 확보합니다.
- 서버가 꼭 필요하지 않으면 로컬 우선 구조를 먼저 검토합니다.

## 완료와 검증

- 코드 작성, 빌드 성공, 설치 성공, 실제 사용 성공, 실기기 성공을 서로 다른 단계로 봅니다.
- 실제 전달 파일과 검증한 파일이 같아야 합니다.
- 변경에 필요한 만큼만 검증하되 검증하지 않은 것을 했다고 말하지 않습니다.
- 중요한 최종 파일은 필요하면 SHA-256까지 남깁니다.

## Windows와 원격 작업

- 관련 작업에서는 UTF-8, 한글 입력, 공백/한글 경로 문제를 확인합니다.
- 원격 데스크톱 연결은 사용자가 켜둔 상태라면 작업이 끝났다고 임의로 끄지 않습니다.
- 작업 중 만든 임시 APK/ZIP/로그/cache/probe/`__pycache__` 등은 종료 전에 정리합니다.
- 최종 산출물, 재현에 필요한 소스·스크립트, 사용자 데이터, 정상 기준판, 원본 자료는 함부로 삭제하지 않습니다.
