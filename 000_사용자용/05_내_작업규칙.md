# 내가 정한 공통 작업 규칙

## 최신 변경 · GitHub 업로드

- 기록은 로컬에 계속 모읍니다. 앱을 켜거나 자료가 바뀌었다는 이유로 자동 업로드하지 않습니다.
- 관리 담당자가 판단해 명시적으로 업로드를 실행할 때만 GitHub에 공유합니다. 아래 이전의 자동 중앙 동기화 안내보다 이 규칙이 우선합니다.
- 잠금이나 저장 거부가 있으면 멈추고 원인을 확인합니다. 작업 중인 파일을 강제로 덮어쓰거나 잠금을 임의 삭제하지 않습니다.

이 규칙은 현재 ChatGPT 프로젝트 안에서만 적용합니다. 다른 Project나 별도 채팅에 자동으로 적용하지 않습니다.

AI가 프로젝트를 작업할 때 지켜야 할 핵심만 사용자용으로 정리합니다.

## 공지 읽고 확인하기

- 모든 연결된 담당 AI는 작업 시작·재개 때 [공지사항](12_공지사항.md)의 새·변경 내용을 읽고 본인 확인 기록을 남깁니다.
- 누가 어느 프로젝트에서 어떤 버전을 읽고 적용했는지 `_통합소통/확인기록`에 남기고, 공유할 요약은 `보낼자료`에 넣습니다. 공지는 `받은공지`에서 읽습니다. 대기·해당 없음·막힘도 구분합니다.
- 관리 앱이 켜진 동안 반복 수집해 중앙에 동기화합니다. 각 담당자의 별도 GitHub 수동 업로드는 요구하지 않습니다. 앱 종료·계정 연결 문제·오프라인·실제 프로젝트 위치 미연결은 대기로 남깁니다.
- 내용이 바뀌면 다시 확인하며 다른 AI를 대신 체크하지 않습니다. 기록 없는 담당자는 미확인입니다.

## 작업 방식

- 요청한 일을 끝까지 처리하고 중간 단계만 해놓고 완료라고 하지 않습니다.
- 정상 동작하던 기준판을 보호하고, 큰 재작성보다 작은 검증된 수정을 우선합니다.
- 기존 코드와 이미 설치된 기능을 먼저 활용합니다.
- 가짜 성공, 임시 placeholder, fake data로 실패를 숨기지 않습니다.
- 위험이 작고 되돌릴 수 있으면 사소한 질문을 반복하기보다 합리적인 기본값으로 진행합니다.

## 자료 확인과 답변

- 요청과 직접 관련된 최신 문서와 파일부터 확인합니다.
- 긴 기록과 저장소 전체를 매번 처음부터 읽지 않습니다.
- 필요한 경우 검색으로 관련 기록을 좁혀서 확인합니다.
- 같은 자료를 반복해서 불러오지 않습니다.
- 답변은 핵심 결과와 근거 중심으로 짧게 정리합니다.

## 새 AI 도구를 고를 때

- 서브에이전트만 늘리지 않고 플러그인·CLI·Skill·문서 검색·검사기·화면 검증도 용도에 맞게 활용합니다.
- 옛날 후보 목록은 참고일 뿐입니다. 더 좋은 최신 방법이 있으면 공식 자료와 실제 환경을 확인해서 비교합니다.
- 필요한 병렬 분업과 Jev 사용은 허용합니다. 매번 사용할 의무는 없고 추가 결제 허가는 아닙니다.
- 문서 확인, 설치, 연결, 실제 기능 실행, 사용자 흐름 완료는 서로 구분합니다.
- 도구를 과하게 쓰면서 생기는 토큰·시간·재작업도 함께 봅니다. 구체적인 추천은 [도구 활용 추천](10_도구_활용_추천.md)에 정리합니다.

- 단순히 설치 가능한지만 보지 않고 **AI가 실제 기능을 혼자 끝까지 다룰 수 있는지**도 따로 표시합니다.
- 설치는 AI가 해도 매번 내가 GUI를 조작하거나 결과를 선택해야 하면 `AI 단독 운용`으로 보지 않습니다.
- 비용은 `무료 / 무료 플랜 / 기존 요금제 포함 / 무료체험 / 유료 / 미확인`으로 나눕니다.
- **추가 결제가 필요한 유료 도구는 기본적으로 다루지 않습니다.** 내가 따로 요청할 때만 검토합니다.
- **기간 제한 무료체험도 웬만하면 사용하지 않습니다.** 무료체험만 가능한 도구는 특별한 이유가 없으면 설치·연결하지 않습니다.
- 우선순위는 `완전 무료·오픈소스 → 기간 제한 없는 무료 플랜 → 이미 쓰는 서비스에 포함 → 무료체험 → 유료` 순으로 봅니다.
- 카드 등록이나 무료기간 종료 후 자동결제가 붙는 것은 무료처럼 취급하지 않습니다.
- 가격이 확실하지 않으면 추측하지 않고 `미확인`으로 둡니다.

## 화면과 사용성

- `현재 상태 → 지금 할 행동 → 결과 → 상세` 순서로 이해하기 쉽게 만듭니다.
- 대표 버튼을 분명히 하고 같은 기능의 중복 버튼을 줄입니다.
- 사람이 알아보는 한글 이름과 용도를 붙이고, 내부 명령·영어 상태·긴 경로는 필요한 상세에서 봅니다. 무엇인지와 눌렀을 때 하는 일을 알려주는 설명만 남깁니다.
- 현재 작업 폴더와 실험·복구·이전 자료를 구분합니다. 휴대폰 설치파일 보기와 PC 프로그램 실행을 섞지 않고, 보관 자료는 기본 접힘으로 둡니다.
- 프로젝트 안내에는 하는 일·시작점·입력·결과·보관 자료의 위치를 적습니다. 이름과 역할을 맞추려고 기존 원본을 자동 이동·삭제하지 않습니다.
- 새 폴더 이름만 보고 목적이나 정상 작동을 추측하지 않습니다. 실제 파일과 최신 안내를 확인하고 다음 AI에게도 같은 기준을 전달합니다. [프로젝트와 폴더 안내](11_프로젝트와_폴더_안내.md)에 현재 구분을 정리합니다.
- 모바일이라고 중요한 기능을 빼지 않습니다.
- 단순 성공 알림을 남발하지 않습니다.
- 삭제·덮어쓰기는 사용자가 명확히 고른 대상에만 적용합니다.

## 데이터와 복구

- 알 수 없는 값과 실제 0을 구분합니다.
- 프로그램 파일과 사용자 데이터를 분리합니다.
- 이미 배포된 ID·저장키·DB 구조는 호환성 계약처럼 다룹니다.
- 큰 변경 전에는 백업/복원 경로를 확보합니다.
- 서버가 꼭 필요하지 않으면 로컬 우선 구조를 먼저 검토합니다.

## 완료와 검증

- 작은 작업은 한 명으로, 독립적인 탐색·재현·검토는 필요할 때 소수로 나눕니다. 동시에 코드를 고칠 때는 담당 파일이나 작업폴더를 분리합니다.
- 에이전트가 많아지면 속도는 빨라질 수 있지만 총 토큰은 늘 수 있습니다. 성공률·완료 시간·재시도·전체 사용량을 함께 확인합니다.
- Jev 키가 있거나 로그인됐다는 것과 실제 작업 전달·완료가 성공했다는 것은 다릅니다.

- 코드 작성, 빌드 성공, 설치 성공, 실제 사용 성공, 실기기 성공을 서로 다른 단계로 봅니다.
- 실제 전달 파일과 검증한 파일이 같아야 합니다.
- 변경에 필요한 만큼만 검증하되 검증하지 않은 것을 했다고 말하지 않습니다.
- 중요한 최종 파일은 필요하면 SHA-256까지 남깁니다.

## Windows와 원격 작업

- 관련 작업에서는 UTF-8, 한글 입력, 공백/한글 경로 문제를 확인합니다.
- 원격 데스크톱 연결은 사용자가 켜둔 상태라면 작업이 끝났다고 임의로 끄지 않습니다.
- 작업 중 만든 임시 APK/ZIP/로그/cache/probe/`__pycache__` 등은 종료 전에 정리합니다.
- 최종 산출물, 재현에 필요한 소스·스크립트, 사용자 데이터, 정상 기준판, 원본 자료는 함부로 삭제하지 않습니다.

## 내가 시킨 일과 AI 답변 남기기

- AI는 **내가 시킨 일 → 실제 답변 → 한 일 → 검증 → 남은 일**을 짧고 쉬운 한국어로 남깁니다. 주요 조건과 출처도 함께 적습니다.
- 같은 일의 진행이 바뀌면 새 버전을 추가합니다. 새 지시가 이전 일을 바꾸면 무엇이 바뀌었는지도 기록합니다.
- 대기·진행 중·완료·막힘·새 지시로 대체를 구분합니다. 일부만 끝났으면 완료로 표시하지 않습니다.
- AI가 읽는 JSON 원본 하나에서 내가 보는 요약을 만듭니다. 파일이 작성된 것과 앱 수집·중앙 공유가 끝난 것은 다르게 표시합니다.
- [기록 방법](../05_TEMPLATES/TASK_EXCHANGE.md). 이 규칙을 배포했다고 모든 AI가 이미 읽었거나 모든 별도 채팅이 저절로 기록되는 것은 아닙니다.

## 각 프로젝트에서 자료 찾기

- 실제 프로젝트 안의 **프로젝트_사용안내.md**에서 무엇을 실행하고 어디서 읽고 듣는지 찾습니다. 입력·최신 결과·참조/비교·이전 자료와 진행 상태를 구분하고 필요하면 이미지로 설명합니다.
- AI도 그 안내를 먼저 읽고 현재 README/규칙/인수인계를 확인합니다. 자료 위치나 사용법이 바뀌면 안내를 같이 고칩니다. 안내가 없으면 실제 자료부터 조사합니다.
- 원본·모델·설치환경은 안내를 만들려고 옮기거나 삭제하지 않습니다. 비밀값·소설 원문·비공개 데이터를 공통 안내에 넣지 않습니다.
- [프로젝트별 안내 지도](11_프로젝트와_폴더_안내.md) · [작성 양식](../05_TEMPLATES/PROJECT_GUIDE.md).

## 2026-10-06 조용한 부팅·종료와 원격 연결
자동 시작·감시·예약 작업은 CMD/PowerShell 창 없이 실행합니다. 확인한 기존 시작 항목을 백업하고 숨김 실행기로 교체하며 기존 작업·미저장 자료는 보호합니다. 원격 연결은 로그인 즉시 시작하고 비정상 종료는 복구합니다. 관리 앱의 의도적 끄기는 이번 로그인 동안 유지하고 다음 로그인에는 다시 켭니다. Windows 종료·로그오프를 막거나 종료 중 다시 실행하지 않습니다. 종료 원인을 확인하지 않고 모든 프로그램을 강제 종료하는 설정은 적용하지 않습니다. 상세 공지: N-0009.

## 2026-10-07 · 연속 작업 승인과 지켜야 할 선

- 옛 Jev 로컬 사용 금지는 폐기했습니다. 기존 사용량 범위에서 필요할 때 선택하며 추가 결제나 Astra 사용은 허용하지 않습니다.
- 프로젝트·명령을 보낸 주체별로 승인된 큐와 다음 단계만 이어가고, 중간 상태·실제 답변·검증·남은 일을 저장합니다. 반복 검사·조회는 가능하면 AI 호출 없이 처리하고, 실행 여부가 불확실한 변경은 무조건 다시 하지 않습니다.
- 바탕화면 파일·폴더·바로가기는 만들거나 고치거나 옮기거나 지우지 않습니다. 창을 재배치하거나 포커스를 빼앗지 않습니다. 기존 바탕화면 입력 자료는 읽기만 합니다.
- 계정·플랫폼 권한 변경, 안전 제한 우회, 원본 대량 삭제, 외부 게시·게시 예약과 추가 결제·무료체험 전환은 이번 작업에 포함되지 않습니다. 권한을 묻지 않게 하는 것은 서비스의 보호 장치를 없애라는 뜻이 아닙니다.
- 모델 목록에 있다는 것과 실제 계정에서 실행되는 것은 다릅니다. 지원 확인된 모델명을 명시하고, 실패·대체 모델·이유는 그 작업 기록에 남깁니다. Astra 제외와 추가 과금 방지를 보장하지 못하는 자동 선택은 쓰지 않습니다.
- 통합 프로그램과 원격 기반을 실제로 확인한 뒤 각 프로젝트 AI에게 최신 공지를 읽고 본인 확인 기록을 요청합니다. 배포·실제 읽음·적용은 다르며 다른 AI의 읽음을 대신 체크하지 않습니다.
- 그다음 Threads 수익화와 무직전생을 최신 안내·기존 수정·평가·제작 상태에 맞춰 이어갑니다. 기존 원격·원본·미저장 자료·생성 중인 오디오북은 보호합니다. 외부 게시와 청취 승인은 별도입니다.
- 이번 규칙을 작성한 것만으로 프로그램 완성이나 모든 AI의 확인이 끝난 것은 아닙니다. [연속 작업·보존 공지 N-0011](../04_COMMUNICATION/announcements/notices/N-0011.md) · [중단 전 기록 공지 N-0010](../04_COMMUNICATION/announcements/notices/N-0010.md).

## 채팅을 끊어도 이어갈 준비

대화가 너무 길어져 끊기기 전에 진행 내용·남은 일·검증·실행 중인 작업·다음 명령을 저장합니다. 지원되는 실행기에서 이미 시작된 작업은 이어가며, 자동 재개가 안 되면 다음에 할 명령을 미리 남깁니다. 새 모델은 사용 가능한 6.1 계열을 우선하고 아스트라는 제외합니다. 모델이 거절되면 실행기 업데이트와 지원 여부부터 확인합니다. 공지 N-0010에 반영했으며 다른 AI의 실제 읽음은 따로 확인합니다.

## 2026-10-07 · 현재 허브 작업의 코드 전용 검증

사용자 최신 지시에 따라 현재 허브 요청 범위에서는 사용자 화면의 live 읽기·직접 스크린샷·UIAutomation·마우스/키보드 입력·포커스나 창 조작을 하지 않습니다. 사용 중인 앱을 닫거나 전환하지 않습니다. 사용자가 첨부한 정지 스크린샷은 참고할 수 있으며 코드·로그·tests·실제 Window를 열지 않는 WPF fixture로 판단합니다.

소스 구현, 코드 검사, 스테이징 파일 준비, 운영 활성화와 실제 사용 검증을 구분하고 미실행을 완료로 적지 않습니다. 기존 일반 UI 검증·화면/이미지 안내 조항보다 이 최신 사용자 제약이 현재 작업에서 우선합니다. 이 제한은 이번 허브 요청 범위이며 다른 독립 프로젝트에 자동 확대하거나 영구적인 모든 UI 금지로 해석하지 않습니다. 새 공지 작성·전파 또는 다른 담당자의 실제 읽음을 완료했다는 뜻도 아닙니다.


## 접근 우선순위 · 2026-10-10 사용자 지시

1. GitHub 직접 연결: 저장소 파일 읽기와 승인된 commit/push/PR.
2. 기존 승인된 ProjectBridge 연결.
3. Codex 로컬 실행 환경: 기존 cloud task에 연결된 사용자 PC에서 본래 파일/셸 도구 직접 사용.
4. 허용된 데스크톱 원격 제어: 앞 경로가 지원하지 않는 작업만 검토.

사용자 PC는 기존 cloud task를 통해서만 접근한다. GitHub 파일은 PC 현재 상태 증거가 아니며 실제 PC 적용 확인 없이 설치 완료라고 하지 않는다. Desktop Commander/remote_desktop_commander는 읽기·상태조회 포함 사용 금지다. 4순위 원격 제어는 이 도구 재사용 허가가 아니다. 새 인증·보안권한 변경·거절·한도 우회는 승인하지 않는다. 중지 상태와 파일별 소유권을 유지한다. `helper_unknown_error: setup refresh had errors`는 명령 실행 전 초기화 실패이고 원인 미확인이면 앱 실제 오류와 구분한다.
