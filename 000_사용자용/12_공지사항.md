# 공지와 자료는 프로젝트 폴더에서

각 프로젝트의 **`_통합소통`**에 다음 세 폴더를 사용합니다.

| 폴더 | 무엇을 하는 곳인가요? |
|---|---|
| `받은공지` | 새 공지와 바뀐 내용을 읽습니다. |
| `보낼자료` | 공유할 안내·진행 요약·인수인계를 넣습니다. |
| `확인기록` | 각 AI가 실제 읽고 적용한 본인 기록을 남깁니다. |

관리 앱이 켜져 있는 동안 공지를 배포하고 자료와 확인 기록을 반복 수집해 중앙에 동기화합니다. **각 담당자가 GitHub에 따로 수동 업로드할 필요는 없습니다.** 원본 자료는 그대로 두고 공유할 짧은 텍스트만 보냅니다. 소통 폴더의 `README.md`에 사용법이 있고, README에 있는 현재 기록 도우미 명령으로 각 AI가 본인 기록을 남길 수 있습니다. 로컬 도우미가 보호돼 갱신되지 않으면 중앙 도우미 명령을 안내합니다.

폴더가 생김, 공지가 도착함, AI가 읽음, 작업에 적용함은 다른 상태입니다. 확인 기록에는 누가·어느 프로젝트에서·어떤 버전을·언제 읽고·어떻게 적용했는지 남깁니다. 다른 AI가 대신 체크하지 않습니다.

앱을 닫으면 반복 수집도 멈춥니다. 오프라인·계정 연결 문제·프로젝트 위치 미연결은 대기로 남기고, 재개했을 때 처리합니다. 로컬에 파일이 있다는 것만으로 중앙 공유 완료라고 하지 않습니다. 프로젝트 메뉴·자동 발견 항목과 실제 연결 폴더 5개, 허브 필수 공지 대상 14개는 서로 다른 수입니다. 실제 폴더가 연결되지 않은 대상은 대기로 남습니다.

현재 공지는 **확인·기록 방법, 사람이 이해하는 화면, 적절한 도구 사용, 공유 원격 연결 보호, 프로젝트 소통 폴더와 자료 정리, 멀티의 신 서버 연결**의 여섯 가지입니다. 첫 공지는 로컬 기록과 자동 수집 방식으로 바뀌어 다시 확인해야 합니다.

멀티의 신은 **게임 개발 폴더**와 **실제 서버 운영 폴더**를 나눠 연결합니다. 같은 게임 안에서 서버 상태를 보되 공지 확인은 각 담당자가 따로 남깁니다. 접속·준비·플레이 인원과 확인 시각을 읽기 전용으로 확인하며, 기존 서버 관리창은 제어 대상 버전이 실제 서버와 달라 시작·재시작이 검증됐다고 표시하지 않습니다. [서버 연결 안내](../ai-control-tower/docs/MULTIPLAYER_SERVER.md)에서 실제 위치와 확인 범위를 볼 수 있습니다.

**[공지사항방](../04_COMMUNICATION/announcements/README.md)** · **[중앙 확인 현황](../04_COMMUNICATION/announcements/STATUS.md)** · [AI 기록 방법](../04_COMMUNICATION/announcements/PROTOCOL.md)

별도 채팅을 자동으로 깨우는 기능은 없습니다. 각 프로젝트의 시작 안내에서 공지와 실제 받은 폴더를 연결합니다.

프로젝트 루트의 `AGENTS.md`에는 통합 소통 진입 안내만 표시된 관리 구역으로 연결합니다. 기존 규칙은 보존하고 구역이 불완전하거나 변경 중이면 보류합니다. 작업을 재개하는 AI가 실제 새 공지를 읽고 본인 기록을 남겨야 합니다.
