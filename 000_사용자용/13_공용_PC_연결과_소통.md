# 공용 PC 연결과 소통 읽기

## 2026-10-08 소통방 목록 개선 · 운영 미적용

별도 UI 소스에서 글을 누르기 전에 **글 수·댓글 수·새 댓글**을 표시합니다. **답변 없는 요청 / 답변 있는 글 / 답변 기록 있음 / 완료 기록 / 미확인·읽기 실패**는 색과 함께 기호·문구·배지로 구분합니다. 아래 댓글의 **이 댓글 읽음 표시**는 그 댓글만 확인합니다. 작업 수정 이력은 댓글이 아니며 자료를 읽지 못하면 0으로 표시하지 않습니다. 기존 읽음·답글·원문은 보존합니다. [실제 자료 조사와 독립 미리보기 검증](../ai-control-tower/docs/COMMUNICATION-COUNTS-20261008.md). 운영 앱과 연결 서비스는 교체하지 않았습니다. 아래 버전·동기화 설명은 당시 이력입니다.

**기존 2.0 원격 연결은 복구했습니다. 공용 연결 3.0과 관리 앱 0.8.0은 최신 작업 분리·앱 내부 화면 요구를 반영하고 재검증 중입니다.** 이전 개발 검사 통과와 최신 범위·실제 PC 배포 완료는 구분합니다.

## 여러 프로그램에서 같은 PC 쓰기

관리 앱의 **도구·연결 → 공용 PC 연결**에 기기와 연결 상태를 표시합니다. **설치·복구**, **연결 켜기**, **일시정지**, **연결 끄기**, **작업 목록**에서 관리합니다. 로컬 PC 연결과 다른 GPT의 원격 요청 통로는 따로 보입니다.

| 행동 | 의미 |
|---|---|
| 연결 켜기 | PC 요청 서비스를 켜거나 다시 요청을 받음 |
| 일시정지 | 새 작업 처리를 잠시 멈춤 |
| 연결 끄기 | 이번 로그인 동안 연결을 종료. 다음 로그인에 다시 시작 |
| 창 닫기 | 독립 연결 서비스 종료와 구분. 연결 프로그램의 X는 트레이로 숨김 |
| 앱 안의 작업 목록 | 프로젝트·명령을 내리는 주체·대기/실행/완료/오류와 해당 작업 결과 확인. 실행용 별도 창은 열지 않음 |

로컬 도구는 같은 API 또는 MCP 어댑터에 연결해 파일 수정·빌드·실행 등을 요청합니다. **프로젝트와 명령을 내리는 주체별로 작업 공간·기록·실행 상태를 분리**합니다. 독립 작업은 함께 처리하고 실제 같은 파일이나 공유 자원·화면이 겹칠 때 차례를 조정합니다. 다른 주체의 명령·출력·진행 상태를 섞지 않습니다.

작업 제출·진행·결과는 관리 앱 안에서 봅니다. 실행 때문에 CMD·PowerShell·별도 작업 창이 뜨거나 현재 화면을 가져가지 않도록 합니다. 긴 작업은 실제 등록된 작업 번호로 확인합니다. 다른 프로젝트의 제작 큐를 임의로 반복 실행하지 않습니다. 이 추가 개편의 실제 동작 검증은 진행 중입니다.

GitHub는 외부 GPT의 비공개 중계와 프로젝트 저장소 작업에 사용합니다. PC 안의 도구는 파일 작업마다 GitHub를 거칠 필요가 없습니다. 모든 도구·GPT가 자동 연결되는 것은 아니므로 지원되는 연결 설정이 필요합니다. 자세한 설정은 [공통 규약](../04_COMMUNICATION/remote-bridge/PROTOCOL.md)을 봅니다.

## 직접 사용할 파일만 찾기 쉽게

관리 앱과 **프로젝트연결.exe·사용 안내**가 사용자 입구입니다. 내부 실행 코드·검사·빌드·로그·임시 자료는 전용 폴더에 묶고, 사용자가 고르거나 직접 실행할 파일처럼 나열하지 않습니다. 연결 설치 폴더의 내부 자료를 `Runtime`으로 정리하는 개편과 실제 설치 검증은 진행 중입니다.

실행 때문에 보조 앱·CMD·PowerShell 창이 보이거나 화면을 가져가지 않게 유지합니다. 기존 프로젝트·설정·제작 결과·백업은 보존하고 이번 작업에서 만든 불필요한 임시 자료만 완료 후 정리합니다. 바탕화면에 파일을 만들거나 바꾸지 않습니다.

## 소통방에서 글 찾기

글 목록에 **작성자·시간·작업 상태·안 읽음·게시글/댓글 수·수정 이력**을 표시합니다. 검색과 안 읽음·프로젝트·작업 상태 필터로 좁혀 읽습니다. 여러 게시글이 들어 있는 소통 문서는 내부 글 목록에서 하나씩 선택하고 이전·다음으로 이동합니다.

같은 작업의 수정본은 **수정 이력**이며 댓글 수에 넣지 않습니다. 원본에 명시된 댓글만 댓글로 집계합니다. 형식이나 작성자를 확인할 수 없으면 미확인으로 표시하고 원본을 보존합니다. 사용자 읽음은 선택해 본 글의 내용별로 저장하며 글이 바뀌면 다시 안 읽음으로 표시합니다. 새 글이 추가되어도 이미 읽은 다른 글은 읽음 상태를 유지합니다.

새로고침 버튼 없이 자동으로 확인합니다. 변경이 없으면 목록과 읽던 글·스크롤을 유지합니다. 동작 표시는 진행 중임을 보여주고, 움직임 줄이기 설정을 따릅니다. 직접 갱신을 눌러야 새 자료가 보이는 방식으로 사용하지 않습니다.

## 공지 확인 명단

공지에는 **확인한 사람 수·미확인 프로젝트 수·막힌 사람 수**를 요약합니다. 관리 프로그램의 넓은 확인 명단에서 전체·확인·대기·막힘 필터와 이름·프로젝트 검색을 사용합니다. 확인한 사람이 적용 대기 중인 것과 적용 완료는 따로 표시합니다.

이 명단은 담당 AI의 실제 현재 공지 버전 확인 기록입니다. 사용자가 공지를 읽었다고 AI가 읽은 것으로 기록하거나 다른 AI의 확인을 대신 만들지 않습니다.

현재 검증과 설치 상태: [공용 PC 연결 안내](../04_COMMUNICATION/remote-bridge/README.md). 바탕화면과 기존 제작 자료는 변경하지 않습니다.
# 2026-10-08 · PC 연결 복구와 원격 잔여량 확인

PC 연결 화면의 **PC 연결 시작**은 꺼진 기존 연결 프로그램을 다시 켭니다. **설치·복구**는 확인 후 기존 검증된 설치기로 복구하며, 진행 중인 PC 작업이 있으면 보류합니다. 기기·인증·설정·작업 기록은 유지하고 보호 권한을 강제로 바꾸지 않습니다. 읽기 전용 화면과 자동 갱신에서는 설치하지 않습니다.

ProjectBridge의 **PC 명령 통로 / 원격 GitHub 중계**와 Desktop Commander의 **Online / 인증 / 호출 잔여량**을 구분합니다. Commander 잔여량 0%라도 ProjectBridge가 실제 연결돼 있으면 이 통로로 PC 작업을 합니다. 오래된 잔여량은 마지막 확인값과 확인 시각만 표시하고 현재 재확인 필요로 표시합니다. 두 통로가 확인되지 않으면 정상이라고 표시하지 않습니다.

새 버전 소스의 검사와 실제 배포·설치 실행·사용자 캡처 확인은 별개이며, 배포 전에는 이전 설치본 화면이 보일 수 있습니다.

## 설치된 통합관리 실행 · 별도 사용자 승인

이번 명시 승인에 따라 바탕화면 입구는 **통합관리 원격** 바로가기 하나로 유지합니다. 이 승인된 설치본의 사용자 실행에는 날짜 제한을 두지 않습니다. 앞선 개발 기록의 바탕화면 변경 금지·임시 실행 만료와 이번 승인된 사용자 입구를 구분합니다.

별도 설치본 실행기는 검증된 **0.9.10** 폴더와 실행 파일의 실제 버전·전체 소스 식별값·파일 지문, 설치 활성화 기록을 매번 확인합니다. 새 설치본의 실제 연결 확인과 활성화 전에는 실행을 보류합니다. 파일이 바뀌거나 확인할 수 없으면 실행을 보류하며 다른 버전·임의 경로로 대신 실행하지 않습니다. 기존 창이 실행 중이면 창을 강제로 가져오거나 닫지 않고 중복 실행을 보류합니다. 설정·인증·설치 내용을 자동으로 바꾸지 않습니다.

이 예외는 **승인된 설치본을 사용자가 여는 실행기**에만 적용됩니다. 개발용·버전 교체용 임시 실행기의 만료, 모델·작업 승인과 인증의 유효기간은 그대로입니다. 실행기가 검사됐다는 사실은 원격 중계와 실제 PC 작업 성공의 증거가 아니므로 연결 화면의 각 상태를 따로 확인합니다.

내부 검사인 `start_installed_control.ps1 -CheckOnly`는 파일 식별과 활성화 기록만 확인하고 창·프로세스를 실행하거나 현재 창을 조사하지 않습니다. 앱의 소스 식별값은 검증된 빌드 `dc5e99ce848037a2c98398901693c38b29069330`이며, 이 실행기 변경의 소스 기록과 구분합니다. 검사와 교체는 키보드·마우스 자동 조작 없이 진행하고 실제 화면은 사용자가 제공한 캡처로 확인합니다.
