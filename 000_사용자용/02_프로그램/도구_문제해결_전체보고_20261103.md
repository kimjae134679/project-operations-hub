## 실제 고친 것: agent-desktop의 암묵적 전경 활성화

공식 v1.0.2 고정 소스 `a47ed664e0db00d1d4df364eb3fe8a5599882f3c`의 UIA 클라이언트가 기본 `AutoSetFocus=true`를 그대로 두었습니다. 원본에서 SetValue만/Invoke만 각각 시행해 **false→true**와 앱 내부 Activated/GotFocus를 분리 재현했습니다. 클라이언트에 `SetAutoSetFocus(false)`를 넣고 실패를 전파하는 **운영 코드6줄의 로컬 수정**으로 고쳤습니다. [Microsoft 공식 속성 설명](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomation2-put_autosetfocus) · [고정 공식 원본](https://github.com/vercel-labs/agent-desktop/blob/a47ed664e0db00d1d4df364eb3fe8a5599882f3c/crates/windows/src/tree/automation.rs).

- 실제 COM getter **RED1FAIL → GREEN1PASS**, client/cache/timeout 및 명시적 focus거부 회귀 **10PASS**, fmt/locked release build PASS. Cargo.lock과 원본 바이너리는 보존했습니다.

- 시작/값설정뒤/버튼뒤 모두 **is_focused=false**, 수동 이벤트 로그의 Activated/GotFocus **0회**. 정확한 테스트 PID/생성신원을 확인해 정상종료·PID소멸·창목록비움까지 PASS. 강제 포커스 복구나 타앱 종료는 하지 않았습니다.

라이선스는 실제 고정 LICENSE의 **Apache-2.0**입니다. 새 정식 upstream 릴리스나 서명 배포물로 가장하지 않습니다. **새 개발콘솔 또는 갱신된 Skill의 절대경로부터 사용**하며 기존 콘솔/프로세스는 재시작하지 않았고 전역PATH·레지스트리·OS COM/보안 설정도 변경하지 않았습니다. 대상 앱/provider가 자체적으로 focus나 dialog를 만들 수 있어 모든 앱·명령의 무간섭을 보장하지 않습니다. 승인된 대상만 한 번 실행→재조회하고 예상치 못한 전경 변화가 있으면 중단합니다.

## 실제 고친 것: OpenMaus가 기존 로그인을 쓰도록 설정

설치 시 `authMode="chatgpt-plan"`은 이름과 달리 **기존 Codex 로그인 재사용이 아니라 앱 전용 별도 인증 홈/컨트롤러**를 선택했습니다. 따라서 기존 로그인만 쓰려던 설정 의도와 달랐습니다.

1. D 앱 데이터 폴더 안에 비공개 백업을 만들고 원본 해시 일치를 확인했습니다.
2. 별도 `authMode`를 제거하고 기존 네이티브 Codex0.160.1 경로와 **이 인스턴스만의** 기존 `CODEX_HOME`을 명시했습니다.
3. `fullAuto=false`, `gpt-6.1-sol`, 기존 유일 인스턴스, 로컬 접근·자동복구/keep-warm 꺼짐은 유지했습니다. API/managed모드·fallback을 추가하지 않았습니다.
4. 실제 수정 전 검사 **4 FAIL/3 PASS → 수정 후 7 PASS**. 기존 Codex 홈·인증 파일·전역 설정·VBS 실행기는 변경하지 않았고 로그인/모델 호출도 하지 않았습니다.

인스턴스 ID는 그대로 유지했습니다. 공식 로더는 단순히 기본 ID `codex`로 바꾸면 여러 공급자 항목을 자동 추가할 수 있기 때문입니다. 기존 `.cmd`도 지원되는 shim이므로 `.cmd` 자체가 고장이라고 보지는 않습니다. `fullAuto`는 원래 미지정 시에도 false였으며 이번 명시는 안전한 의도를 고정한 것입니다.

이 수정은 **확인된 인증 선택 설정 오류 해결**입니다. 실행 정책 차단까지 해결했다거나 앱 E2E가 통과했다고 하지 않습니다. [고정 공식 드라이버](https://github.com/milind-soni/OpenMausBot/blob/acbac2139d0839fb3587fc60e2aeb083e1afe842/server/drivers/codex.ts) · [공식 설정 로더](https://github.com/milind-soni/OpenMausBot/blob/acbac2139d0839fb3587fc60e2aeb083e1afe842/server/config.ts).

## 왜 실행이 막혔나

- 기록상 확정된 지점은 **실행 도구/정책 경계, 요청한 자식 프로세스 실행 전**입니다. 오류에 정확한 rule ID·Windows 오류코드는 없었습니다. 이 사실만으로 악성코드, 백신, UAC, 제품 결함을 판정하지 않습니다.
- 원래 Codex 과제 harness가 `--ignore-user-config`를 사용해 저장된 Windows sandbox 선택을 제외한 것은 확인된 **검사 구성의 혼입 변수**입니다. 실제 자식에게 적용된 구현은 노출되지 않았으므로 이것을 원인으로 확정하거나, 설정을 바꾸어 거절된 과제를 다시 시도하지 않았습니다.
- 사용자 rules의 읽기 전용 정적 검사에서 일치한 규칙이 없었다고 해서 전체 host/managed 정책이 허용한다는 뜻은 아닙니다. 관련 시각 sandbox 로그가 없다는 것도 차단 주체를 특정하지 못합니다.
- 지원 가능한 다음 단계는 실행 호스트 담당자가 기존 기록의 시각·명령 유형으로 **결정한 규칙/범주와 지원되는 진단 경로를 확인**하는 것입니다. 광범위 allowlist·규칙 무시·full-access·권한 상승·다른 실행기로의 우회는 하지 않습니다.

### 별개: 내부 진단용 OpenMaus 비번들 CLI의 한계

앞선 `ERR_MODULE_NOT_FOUND`는 조사자가 내부 `resources/server/server/openmausbot.js`를 별도로 호출한 결과입니다. **사용자에게 설치한 CLI 실행기가 아닙니다.** 정상 사용자 입구는 `OpenMausBot.lnk → D-data VBS → 정상 EXE`입니다. 실제 app.asar를 실행 없이 읽어 package.main=`electron/main.mjs`와 `companion-account-service.mjs`의 존재를 확인했고, 관련 main/loader/companion 세 파일은 고정 공식 소스와 바이트가 같았습니다. Desktop loader의 `desktop-entry.mjs → 번들 index.js`도 존재합니다. 따라서 내부 비번들 트리의 상대경로 누락을 정상 GUI 설치 결함으로 보지 않으며, vendor 파일 복원/복사/대체 실행은 필요·지원된 수정으로 확인되지 않아 하지 않았습니다. 정상 GUI runtime은 이와 별도로 정책 차단 때문에 미검증입니다.

## 인증·워크플로가 필요한 것과 설치 결함의 구분

- **Apify:** 공개 문서2도구는 무인증 사용 가능하고 실제 조회했습니다. Actor는 공식 인증 게이트상 토큰이 필요합니다. 현재 토큰/정상 auth파일의 **존재 여부만 false**를 확인했으며 값을 읽지 않았습니다. ChatGPT로그인으로 대체되거나, 로컬 MCP 설치만으로 모든 클라우드 Actor가 무료가 되지 않습니다. 기존 Apify 계정·승인된 자격증명/사용량 조건이 생기기 전까지 Actor는 비활성입니다. [공식 인증 코드](https://github.com/apify/apify-mcp-server/blob/v0.20.0/src/utils/auth.ts).
- **Replica:** helper는 표준 Python이며 별도 paid API 설치 전제가 없습니다. 기존 Codex에서 작업에 맞는 skill을 선택합니다. 완전한 워크플로는 구체적 대상·프로젝트·승인된 모델 작업이 필요합니다. 인증/결제/배포 계정은 해당 작업에서만 필요하며 자동 가입·실결제·보안 우회는 하지 않습니다. [고정 원본](https://github.com/Jakeschincariol/replica-skill/tree/77c9436fb3d18c3d58169efb8caf4fe906b0dc51).
- **T3:** 기존 Codex0.160.1은 고정 공식 호환 manifest의 최소0.156/권장0.159이상에 해당합니다. 기존 binary/home, Supervised·Sol·fallback없음·Claude꺼짐, 두 실행기 목표 파일/telemetry설정은 정적 검사 PASS입니다. 특정 모델 권한·runtime 적용은 미검증입니다. 누락 API 키/Node/VC++가 원인이라는 근거 없이 무차별 설치하지 않았습니다. `doctor`는 DB유지보수이지 healthcheck가 아닙니다. [공식 호환 manifest](https://github.com/pingdotgg/t3code/blob/2359643cffa6ba9ee84d6f2694b935de54a8013e/apps/server/src/provider/model-manifest.json).

## 지금 사용 순서

1. 코딩/자료수집은 기존 Codex·GitHub·ProjectBridge와 개발 콘솔의 읽기 전용 파일 도구를 우선합니다.

3. OpenMaus/T3는 설치되어 있지만 정상 기동·연결 검증이 남았으므로 업무 완료를 보장하는 주 도구로 간주하지 않습니다.
4. agent-desktop은 새 콘솔/갱신 Skill의 로컬 수정본을 사용하되 허가한 앱만 한 번 조작→새 결과를 재조회합니다. 이번 자체창 비간섭 통과를 모든 앱의 안전보장으로 확대하지 않습니다.

새 결제·구독·계정·Actor실행·자동시작·전역PATH·보안완화는 하지 않았습니다. 로그·인증파일·개인 config는 공개 저장소에 싣지 않았습니다. 원본 설치 이력과 새 수정 결과는 날짜·단계를 구분하며, 남은 BLOCKED/NOT_RUN을 완료로 지우지 않습니다.

## Key Learnings:

1. 설치 오류, 설정 선택 오류, 인증 전제, 실행 정책 차단, 아직 실행하지 않은 워크플로는 서로 다른 상태입니다.
2. OpenMaus의 별도 ChatGPT-plan모드를 제거하면 기존 Codex홈을 선택할 수 있지만, 실제 앱 실행 검증을 대신하지는 않습니다.
