# 컨트롤타워 사용법

## 현재 진행 순서

외출 중 직접 확인 없이, 화면·마우스·키보드를 건드리지 않고 코드·로그·검사로 원격 실행·연속 작업·기록 기반부터 마무리합니다. Threads 수익화와 Voice의 새 작업은 이후에 진행하며, 이미 생성 중인 오디오북과 기존 평가·자료는 보존합니다.

명령·이미 전달한 답변·결과·남은 일은 로컬 이력에 저장합니다. **로컬 저장 / 앱 수집 / 중앙 공유**는 따로 확인하며, 공유가 막혀도 저장된 기록과 진행 작업을 다시 실행하지 않습니다. 전체 대화가 자동 백업됐다는 뜻은 아닙니다.


여러 프로젝트의 **프로그램과 자료를 한곳에서 찾고**, 용도를 확인한 뒤 열기·실행·중지하는 Windows 관리 앱입니다. 현재 **0.9.3 manual-control(PID 16092)**을 실행했고 원격 supervisor(PID 5996)는 별도로 유지합니다. 이전 소유 조회앱 PID 376만 정상 종료했습니다. 프로젝트·프로그램·자료 수는 실제 폴더 자동 발견에 따라 바뀌며, 문서·폴더·설치파일도 포함하므로 모두 실행 프로그램인 것은 아닙니다.

화면 왼쪽의 세로 메뉴에서 작업 공간을 바꿉니다. 프로젝트·프로그램 목록 위에서 마우스 휠로 이동할 수 있습니다. 큰 창은 프로그램 카드 두 열, 작은 창은 한 열로 표시합니다.

## 내 프로젝트

1. 왼쪽에서 프로젝트를 선택합니다. 이름과 설명으로 하는 일을 확인하고, 검색으로 찾을 수 있습니다.
2. 가운데에서 필요한 프로그램이나 자료를 선택합니다. 기능별로 나뉘어 있으며 항목 검색도 가능합니다.
3. 오른쪽에서 무엇인지와 할 일을 확인합니다. 제작 화면은 열고, 휴대폰 설치파일은 위치를 보고, 음성 결과는 폴더에서 골라 듣습니다.
4. 실행한 작업은 중지하거나 **작업 기록**을 펼쳐 결과를 확인합니다. 폴더 위치와 자세한 기록은 필요할 때만 펼칩니다.

설명과 연결을 등록한 주요 프로젝트는 **멀티의 신, 무직전생 오디오북, 영상·음원 저장, 전체 프로젝트 관리, 주식 자동매매, 청약 도구**입니다. 추가 발견 항목은 용도를 확인하기 전까지 후보로 구분합니다. 게임의 이전 개발본·실험 사본·복구 자료와 오디오북 코드 보관본은 주 작업과 구분합니다. 각각 어디서 무엇을 하는지는 [프로젝트와 폴더 안내](11_프로젝트와_폴더_안내.md)를 봅니다.

게임의 최근 작업용 APK와 사용자 확인 완료본을 구분하며, APK를 PC 게임 실행파일로 표시하지 않습니다. 주식·청약은 조사 당시 빈 준비 폴더로 실행 기능이 없습니다. Unity 편집기와 기존 열기 스크립트를 확인해 `Unity로 열기`를 연결했습니다. 편집기 실행 자체는 이번 검증에서 수행하지 않았습니다.

### 2026-10-07 안전한 로컬 기록 수집

CollectOnlyAsync 소스와 회귀 22개, 전체 코드 기반 .NET 432개가 통과했습니다(창을 만드는 기존 3개 제외). 실제 4개 프로젝트의 기존 기록 273건을 독립 D 소유 수집 폴더에 보존했습니다: 관리 116 / 오디오북 71 / 콘텐츠 13 / 게임 서버 73. 원본·clone·Git·설정·공지 확인 생성은 변경하지 않는 경로입니다. 수집은 중앙 공유나 다른 AI의 읽음/적용이 아닙니다. 현재 실행 중 0.9.3 앱에는 이 새 수집 API의 화면·자동 루프 연결을 아직 반영하지 않았습니다. 소스 구현/직접 호출 검증과 앱 배포를 구분합니다.

10:17~18에는 앱의 PC 연결 표시가 false인 샘플을 다시 관찰했습니다. 10:19 purpose-built 상태는 worker5140 localReady/relayConnected true, 별도 Remote Desktop은 pong, 앱 기록도 true로 복구했습니다. 앱의 bool-only 기록으로 timeout/backoff/오류 원인을 확정하지 않았으며 연결이 계속 끊겼다고 단정하지 않습니다. timeout/freshness 변경 없이 정제된 단계·소요시간 진단을 다음 수정으로 남깁니다.

상태 파일 연결이 거절되거나 연결 기능이 없을 때 성공으로 표시하던 문제를 수정했습니다. 연결 확인과 기록 조회의 실패·취소는 별도로 표시하며, 상태 연결은 작업 실행이 아닙니다. 새 회귀 검사 8개와 부모의 전체 코드 기반 검사 537개가 통과했습니다. 창을 만드는 기존 휠 검사 3개는 제외했습니다.
