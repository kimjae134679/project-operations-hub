# AI 도구·플러그인 사용 구분

이 문서는 **무엇을 지금 바로 쓸 수 있는지, AI가 혼자 끝까지 다룰 수 있는지, 내가 도와줘야 하는지, 무료인지, 설치가 얼마나 무거운지**를 사용자 기준으로 빠르게 보기 위한 문서입니다.

## 표기

### AI가 혼자 다룰 수 있는 정도
- `AI 단독 가능` — 필요한 입력만 있으면 AI가 기능을 처음부터 끝까지 처리 가능
- `1회 준비 후 가능` — 로그인/OAuth/UAC/API key 같은 준비만 내가 한 번 해주면 이후 대부분 AI가 처리 가능
- `부분 가능` — AI가 많이 처리할 수 있지만 GUI 선택·시각 확인·수동 단계가 자주 필요
- `사용자 중심` — 핵심 사용은 내가 직접 해야 함
- `미확인` — 실제 운용성 검증 전

### 비용
- `무료` — 완전 무료/오픈소스로 자체 사용 가능
- `무료 플랜` — 기간 제한 없는 무료 구간이 있으나 사용량 제한 가능
- `기존 요금제 포함` — 내가 이미 쓰는 서비스 안에서 추가 결제 없이 사용
- `무료체험` — 기간/크레딧 제한 체험
- `유료` — 추가 결제 필요
- `미확인` — 공식 가격을 아직 확인하지 못함

### 설치 부담
`⚪ 없음 / 🟢 가벼움 / 🟡 보통 / 🟠 무거움 / 🔴 매우 무거움`

## 내 기본 선택 기준

**유료 도구는 기본적으로 제외합니다.** 내가 따로 요청할 때만 봅니다.

**무료체험도 웬만하면 사용하지 않습니다.** 무료체험만 가능한 서비스보다 완전 무료·오픈소스나 기간 제한 없는 무료 플랜을 먼저 찾습니다.

`무료·오픈소스 → 무료 플랜 → 기존 요금제 포함 → 무료체험 → 유료`

카드 등록이 필요하거나 체험 종료 후 자동결제되는 것은 무료처럼 취급하지 않습니다. 가격을 모르겠으면 `미확인`으로 둡니다.

### `mise`를 추가한 이유

`mise`는 프로젝트별 Node.js/Python/Go 등 개발도구 버전, 환경변수, build/test 같은 task를 `mise.toml`에 선언할 수 있습니다. 새 AI 세션이나 새 PC에서도 같은 파일을 읽고 `mise install`, `mise run`으로 환경을 재현하기 쉬워 **AI가 프로젝트마다 설치법을 다시 추측하는 문제를 줄이는 후보**입니다.

Windows는 공식 문서에서 `winget install jdx.mise` 설치를 지원합니다. shell activation을 꼭 하지 않아도 `mise exec`/`mise run` 방식으로 사용할 수 있어 자동화에도 유리합니다.

다만 `mise.toml`은 도구 설치와 task 실행을 지시할 수 있으므로 외부 저장소에서 처음 보는 설정은 실행 전에 내용을 검토합니다. 또한 `mise` 자체가 무료라고 해서 이를 통해 설치하는 제3자 SDK·패키지·API까지 무료라는 뜻은 아닙니다.

`uv`는 Python에 집중하고, `mise`는 여러 언어/SDK의 버전과 프로젝트 전체 환경을 묶는 쪽이라 역할이 다릅니다. 이미 단순한 프로젝트에 억지로 도입하지 않고 여러 런타임 버전이 섞이거나 환경 재현 문제가 반복될 때 우선 검토합니다.

### `fd`와 `just`를 추가한 이유

`fd`는 MIT/Apache-2.0 무료 오픈소스이며 Windows를 포함해 사용할 수 있습니다. `rg`가 파일 **내용** 검색에 강하다면 `fd`는 파일·폴더 **경로**를 빠르게 찾는 역할이라 AI의 대형 프로젝트 탐색에서 서로 보완됩니다.

`just`는 CC0-1.0으로 공개된 무료 command runner이며 Windows에서도 PowerShell/cmd를 shell로 지정할 수 있습니다. 프로젝트마다 서로 다른 긴 빌드·테스트 명령을 `justfile`에 이름으로 고정하면 새 AI 세션에서도 실행법을 다시 추측할 필요가 줄어듭니다. 단, `just`가 실행하는 실제 recipe가 안전한지는 별개이므로 저장소에서 처음 보는 `justfile`은 내용을 확인한 뒤 실행합니다.

### `uv` 메모

`uv` 자체는 MIT/Apache-2.0 이중 라이선스의 무료 오픈소스이고 Windows/macOS/Linux를 지원합니다. Python 자체가 없어도 공식 standalone installer로 설치할 수 있으며 Python 버전 설치, 가상환경, dependency lock/sync, Python CLI 도구 실행까지 묶어서 처리합니다. 따라서 여러 AI 프로젝트에서 `pip + venv + pipx + pyenv` 식으로 환경 관리 방식이 갈리는 것을 줄이는 AI 작업용 기반 도구 후보로 가치가 큽니다.

주의할 점은 `uv`가 무료라는 것과 `uv`로 설치하는 제3자 Python 패키지/API가 무료라는 것은 별개라는 점입니다. 또한 패키지 build 과정에서는 Python 생태계 특성상 외부 코드를 실행할 수 있으므로 출처 불명 패키지를 무조건 설치하는 용도로 쓰지 않습니다.

### Gitleaks에서 구분할 것

`Gitleaks CLI`와 `gitleaks-action`은 같은 것으로 취급하지 않습니다. 로컬 CLI는 무료 오픈소스지만 GitHub Action은 별도 조건이 있습니다. 특히 **2026-09-16부터 GitHub-hosted runner에서 Node 20이 제거되어 `gitleaks-action@v2`는 더 이상 동작하지 않는다고 공식 안내**되어 있으므로 Action을 쓸 때는 v3/runner 조건을 다시 확인합니다.

### Context7에서 구분할 것

무료 플랜은 공개 라이브러리 문서 조회에 쓰는 방향만 기본 후보로 둡니다. Private repository 기능은 유료이므로 사용자 기본 정책상 제외합니다.

## AI가 혼자 다루기 좋은 계열

단일 CLI, 프로젝트 내부 Skill/스크립트, API/MCP/Plugin처럼 기능이 직접 노출되고 로그인·결제·CAPTCHA가 없는 도구가 가장 좋습니다. 설치만 AI가 할 수 있는 것과 실제 기능까지 AI가 혼자 운용할 수 있는 것은 다르게 표시합니다.

## 내가 직접 써야 하는 비중이 큰 것

- `ComfyUI` — 부분 가능~사용자 중심
- `Blender` — 자동화 가능하지만 최종 형태·재질 확인 필요
- `Canva`, `Figma` — 최종 디자인 선택은 직접 검수 가치가 큼
- `Dify`, `Langflow`, `Open WebUI`, `LobeHub` — 플랫폼 UI 자체를 직접 운영하는 유형
