# 작업에 맞게 도구를 활용하는 방법

**서브에이전트·플러그인·CLI·Skill·검색·검사기·Jev를 필요한 일에 맞게 조합합니다.** 예전에 모아둔 후보는 참고일 뿐이고, 더 좋은 최신 방법도 계속 비교합니다.

| 이런 작업이면 | 활용할 것 | 과하게 쓰면 생기는 문제 |
|---|---|---|
| 코드·이전 기록 찾기 | 빠른 파일 검색과 필요한 GitHub 파일 조회 | 저장소·긴 채팅 전체 반복 로딩으로 토큰 낭비 |
| 최신 API 확인 | 공식 문서와 Context7 | 같은 자료 중복 검색, 다른 버전 코드 혼입 |
| 외부 앱 파일·상태 작업 | 해당 서비스 플러그인·connector | 연결·권한·응답 대기 부담 |
| 반복 작업 | 관련 Skill과 기존 스크립트 | 관련 없는 절차를 전부 읽으면 문맥·관리 부담 |
| 코드 오류 확인 | 프로젝트의 검사기·빌드, Python Ruff·PowerShell PSScriptAnalyzer | 검사 중복, 무관한 전체 수정. 검사 통과와 실제 사용 성공은 다름 |
| 화면·버튼 검증 | 제공된 브라우저 기능, 환경에 맞는 Playwright | 큰 화면 자료·로그·세션 유지 비용 |
| 이미지·영상·음성 대량 처리 | 생성 도구와 FFmpeg/ffprobe·배치 처리 | 기기 자원 경쟁, 불필요한 재변환과 품질 손실 |
| 독립적인 조사·재현·검토 | 소수 서브에이전트로 병렬 분업 | 총 토큰·중복 조사·코드 충돌 증가 가능 |
| 간단한 작업과 복잡한 작업 혼합 | Jev와 직접 Codex 실행 비교 | 라우팅 대기·모델 선택 실패 후 재작업 가능 |
| 반복 실행·전체 관리 | 기존 실행기의 큐·상태·결과 연결 | 단순한 일에 무거운 시스템을 붙이면 유지관리 증가 |

작은 수정은 한 명으로 처리하고, 서로 독립적인 일은 필요한 만큼 나눕니다. 동시에 코드를 고치면 담당 파일이나 작업폴더를 분리합니다. 구현이 나온 뒤 별도 검토를 붙이고, 검증 증거로 완료를 판단합니다.

에이전트가 많으면 빠르게 끝날 수 있지만 **전체 토큰은 늘 수 있습니다.** 완료 시간·성공률·재시도·전체 사용량을 함께 확인합니다. 긴 대화나 로그를 모두에게 반복 전달하지 않습니다.

**Jev 사용은 허용됐습니다.** 매번 사용할 의무나 추가 결제 허가는 아닙니다. 모델을 고르는 라우터이고, 프로젝트 발견·작업 실행·검증·결과 전달은 실행기가 맡아야 합니다. 설치·키 설정·로그인이 확인됐다는 것과 실제 연동 성공은 다릅니다.

이번 정리에서 Context7은 현재 세션 도구 제공을 확인했고, 여러 추천 도구는 공식 문서를 확인했습니다. 이 표 자체가 신규 설치나 해당 프로젝트 실사용 성공 기록은 아닙니다. 상태는 **문서 확인 → 설치 확인 → 연결 → 기능 실행 → 사용자 흐름 완료**를 구분합니다.

새 AI 작업은 최신 D드라이브 지시와 PC 관찰에 따라 `D:\A_KJ\AI`를 기본값으로 씁니다. 기존 도구가 전부 이동됐다는 뜻은 아니며 실제 경로는 따로 확인합니다.
