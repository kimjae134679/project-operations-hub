# 사용자 요청: 프로젝트마다 보기 편한 진행 UI를 검토하고 실제 시도하기

수신: 2026-10-07 19:01:15 KST
출처: 무직전생 오디오북 담당 ChatGPT 대화의 직접 사용자 지시
작성: Codex-Mushoku-next-20261007
전달 대상: 통합소통/컨트롤타워 관리 담당자, 각 프로젝트 담당자
상태: 요청 전달. 전체 프로젝트 구현 완료나 담당자 확인을 뜻하지 않음.

## 받은 지시

각 프로그램과 프로젝트마다 사용 방식과 필요한 정보가 다르다. 사용자는 매번 채팅에서 “몇 퍼센트 됐어?”, “얼마나 진행됐어?”라고 묻지 않아도 현재 진행을 쉽게 보고 싶어 한다. 오디오북에서도 퍼센트를 시각적으로 보고 싶다고 요청했고, 이 요구를 통합소통에 전달하라고 명시했다.

각 프로젝트만의 용도와 흐름에 맞게, 진행률과 작업 상태를 매우 보기 편한 UI로 구현하는 방법을 고민하고 이제 실제 시도를 시작해 달라. 통합툴이든 프로젝트 프로그램이든 적합한 위치와 방법을 검토한다. 사용자가 확인하는 채팅에서도 실제 확인한 진행률과 완료/전체 수량을 짧게 알려 주는 흐름을 함께 고려한다.

## 검토와 첫 시제품 요청

1. 각 프로젝트에서 사용자가 자주 확인해야 하는 정보와 실제 측정 가능한 진행 단위를 먼저 파악한다. 예: 오디오북은 완료/전체 회차, 현재 회차, 음성 생성·검증·게시 단계, 현재 회차 안의 처리량.
2. 큰 퍼센트와 진행 막대, 완료/전체 수량, 현재 하는 일, 남은 작업과 대기·실패·일시정지 상태를 한눈에 볼 수 있는 프로젝트 전용 화면을 설계한다. 정보와 조작은 프로젝트 성격에 맞춘다.
3. 통합 관리 화면에서는 프로젝트별 핵심 상태를 간단히 보고, 해당 프로젝트의 자세한 화면으로 쉽게 이어지는 방법을 검토한다. 프로젝트 전용 화면과 통합 화면 사이의 역할, 공통으로 교환할 상태 정보와 갱신 방법을 제안한다.
4. 한 프로젝트의 작은 시제품부터 실제 데이터로 연결해 사용해 보고 확장한다. 검토 문서만 남기지 말고 화면과 실제 상태 연결을 시도한다. 기존 프로그램 구조와 진행 중 작업을 보존하며 각 담당자의 권한과 사용자 지시 범위에서 구현한다.
5. 실행 중 자동 갱신과 마지막 확인 시각을 보여 준다. 연결이 끊겼거나 오래된 상태는 구별한다. 전체량을 모르는 작업은 가짜 퍼센트를 만들지 않고 현재 단계와 처리량을 보여 준다.
6. 전체 완료율과 현재 작업 내부 진행을 구별한다. 큰 단위가 오래 걸려 전체 퍼센트가 그대로일 때도 실제로 무엇이 진행 중인지 알 수 있게 한다. 남은 시간은 근거가 있을 때만 추정 표시한다.
7. 사용자가 프로그램을 실제로 켜서 편하게 확인하는 흐름을 검증한다. 처음 열기, 작업 실행, 진행 확인, 완료 결과 열기, 대기/실패 상황을 확인하고, 시제품 위치·변경 내용·검증 결과·남은 일을 통합소통에 기록해 달라.
