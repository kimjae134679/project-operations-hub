# 001 — Sol

사이드메모장은 지금 기능을 더 많이 넣기보다 **배포와 편집기의 신뢰성을 먼저 고정하는 편이 낫다**고 봅니다.

최근 실제 작업에서 드러난 문제는 세 가지였습니다.

1. GitHub Release에서 태그/`latest.yml` 이름이 조금만 어긋나도 기존 설치본의 업데이트가 바로 404로 깨졌습니다. 다음 버전부터는 `vX.Y.Z`, `latest.yml`, Setup 파일명, package 버전, SHA-512/size를 한 번에 검증하는 **release gate**가 필요합니다.
2. Ctrl+B, Ctrl+Shift+X, 이미지 Ctrl+C/X/V/Z처럼 contenteditable 선택 상태에 의존하는 기능은 겉으로는 단순하지만 첫 글자까지 드래그하거나 툴바를 누르는 순간 selection이 풀리는 식의 경계 문제가 많았습니다. 다음 작업은 기능 추가보다 **선택/undo/clipboard 회귀 테스트를 묶어서 고정**하는 게 먼저입니다.
3. 이미지 이동처럼 사용감이 애매한 기능은 과감히 빼는 게 오히려 앱을 좋아지게 했습니다. 사이드메모장은 작은 도구인 만큼 기능 수보다 `안 깨짐`, `바로 됨`, `데이터가 안 날아감`이 핵심입니다.

다음 버전 후보로는 자동 백업/버전 복원, 전체 메모 검색, 즐겨찾기, 체크리스트 개선이 실사용 가치가 높아 보입니다. 다만 이 네 가지도 한 번에 다 넣기보다 **배포 안정화 → 편집기 QA → 백업/복원 → 검색** 순서가 안전합니다.

그리고 `04_COMMUNICATION` 자체는 꽤 쓸모가 있습니다. 채팅에서 나온 결정이 다음 채팅으로 넘어갈 때 사라지는 문제가 많은데, 여기에는 "왜 이렇게 결정했는지"만 짧게 남기고 실제 확정 규칙은 프로젝트 README/CONTROL 쪽에 옮기는 구조가 맞아 보입니다.
