## Exact implementation

### Bounded staging model

Added `media-staging.mjs`.

- only PNG/JPEG/WebP rendered image data URLs are accepted
- maximum 10 assets and 5 MiB per asset
- staged filenames are server-generated UUIDs; arbitrary filesystem paths are never accepted
- runtime default is the ignored `data/runtime/media-staging` area
- files request mode `0600`
- `PUBLIC_MEDIA_BASE_URL` must be a public HTTPS origin; localhost, loopback/private IPv4 and `.local` origins fail closed
- `MEDIA_STAGING_ENABLED=1` is separately required before staging becomes `ready-to-validate`
- generated URLs remain explicitly `staged-unverified`; configuring a public-looking origin does **not** claim external/provider reachability
- staged URL validation accepts only the configured origin and bounded `/media/staged/<uuid>.<ext>` paths, with no query/fragment values
- partial writes are removed on failure

Capability states are explicit:

- `public-origin-required`
- `live-disabled`
- `ready-to-validate`

### Instagram media dry-run model

Added `instagram.mjs`.

The module intentionally does not guess a current Graph API version or permission list. It requires operator-supplied configuration for all of:

- `INSTAGRAM_ACCESS_TOKEN`
- numeric `INSTAGRAM_USER_ID`
- `INSTAGRAM_GRAPH_API_VERSION` in `vN.N` form
- non-empty `INSTAGRAM_REQUIRED_SCOPES`

`INSTAGRAM_MEDIA_LIVE_ENABLED=1` is an additional explicit switch. Capability state is:

- `credential-required`
- `live-disabled`
- `ready-to-validate`

Feed/carousel dry-run supports one IMAGE or up to 10 CAROUSEL images and builds the intended official Graph request sequence without executing any upstream request. Returned plans record `externalCalls: 0` and `livePublishImplemented: false`.

No provider credential, token or secret is committed or persisted.

### Server route integration

`media-publish-routes.mjs` is now wired into `server.mjs` before static serving. It exposes:

- `GET /api/media-staging/capabilities`
- `POST /api/media-staging/stage`
- `GET /media/staged/<server-generated-id>`
- `GET /api/instagram/media/capabilities`
- `POST /api/instagram/media/dry-run`

Both mutation/dry-run paths reuse the existing full `validateApprovedCandidate()` gate, so status/score/research review/draft approval/rights-safety review/current publish approval all remain required. Instagram dry-run only accepts URLs generated under the configured staging origin and returns `publicationOwner: 04_REVIEW_PUBLISH`, `livePublicationAttempted:false`.

`/api/connectors` now reports non-secret staging and Instagram capability snapshots. The generic request body remains 256 KiB; only staging opts into a bounded 24 MiB ceiling for rendered image payloads.
