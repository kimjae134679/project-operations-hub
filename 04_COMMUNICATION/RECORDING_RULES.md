# 통합소통 기록 규칙

작성: 2026-11-12 KST · 마지막 수정: 2026-11-12 KST.
확인 범위: 기존 task_exchange 스키마·필드와 문서 연결을 대조한 기록이다. 개별 도구의 새 실행·품질 확인일을 뜻하지 않는다.
통합소통을 새로 작성·갱신할 때만 적용한다. 매 턴 형식 로그·전체 공지 필독·전체 채팅 업로드를 강제하지 않는다. 분류·정리는 AI가 맡고 사용자에게 JSON이나 스킬명을 배우게 하지 않는다.

## 무엇을 어디에 적는가
| 분류 | 위치와 용도 | 유지 기준 |
|---|---|---|
| 현행 규칙 | 01_CONTROL의 현재 정책 1개, AGENTS는 진입 포인터 | 안정된 이름으로 현재본 유지. 과거판은 보관·대체 링크 |
| 사용 중 도구·스킬 | [설치 현황](../01_CONTROL/AI_INSTALLATIONS.md)과 실행 환경의 공식 스킬 루트 | 설치·파일 존재·실행·실사용·품질을 구분 |
| 사용법·예시 | 필요할 때만 03_KNOWLEDGE/HOWTO/<대상>/ | 원래 설명·이미지·설정 예제·라이선스를 대상별 묶음으로 |
| 작업 이력 | 같은 주제의 기존 THREAD 댓글과 실제 task_exchange 원본 | append·revision·supersedes로 연결. 매 턴 복제 문서 금지 |
| 참고 자료 | 03_KNOWLEDGE/<주제>/ | 원문 사실·출처·발행일과 AI 평가를 분리 |
| 보관·폐기 | 99_ARCHIVE/YYYY-MM-DD/<주제>/ | 보관 이유·대체 현행·원문과 첨부·복원 위치 표시 |

현행 규칙·사용법은 날짜별로 복제하지 않고 안정된 경로를 쓴다. 원본·최종 결과·참고 자료·다시 만들 수 있는 자체 임시물을 구분한다.
작업과 보관은 날짜로 정리하되, 원래 설명·그림·예시·라이선스는 관련 대상과 함께 보존한다. 원문 이력은 가짜 새 기록으로 바꾸지 않는다.

## 날짜·설명·확인 상태
- 작성일, 마지막 수정일, 실제 확인일, 원문 발행일, 스크린샷 촬영일, 보관일은 서로 다르다.
- 파일 mtime은 촬영일·발행일·사용일의 증거가 아니다. 모르는 발행일·촬영일은 미상으로 둔다.
- 실제 확보한 시각과 출처를 쓰고 KST 또는 ISO 8601의 +09:00 등 시간대를 표시한다. AI가 추측한 날짜나 과거로 소급한 실행 기록을 만들지 않는다.
- 필요한 범위에서 분류·제목·대상/용도·실제 작성자·날짜·설명/요약·확인 상태·출처/관련 파일·현재본/이전본/다음 행동을 적는다.
- AI 평가는 원문 사실과 별도 표시하고, 검증 전 의견을 실제 결과로 쓰지 않는다.
- 다시 사용할 때 실제 존재·버전·현재 지시·마지막 확인 상태를 먼저 대조한다. 과거 설치 성공은 현재 동작, 과거 평가는 현재 성능의 보장이 아니다.
- 새 PC 전용 경로만 적지 말고 어떻게 여는지·무엇에 쓰는지도 짧게 설명한다. 설명과 비민감 첨부는 같은 대상 묶음과 상대 링크로 연결한다.

## 기존 기록 형식에 맞추기 — AI 작성 기준
[기존 JSON 스키마](../05_TEMPLATES/TASK_EXCHANGE.schema.json)와 [기존 작성 방법](../05_TEMPLATES/TASK_EXCHANGE.md)을 그대로 사용한다.
추가 최상위 필드는 허용되지 않는다. category/date/sourceDate 같은 키를 새로 만들거나 앱 파서를 바꾸지 않는다.

- 분류는 title의 [사용법]·[참고]·[작업] 같은 짧은 접두어로 표시한다.
- 용도·원문 발행일·AI 평가는 request.details / response.details 안에 사람이 읽는 라벨로 적는다.
- receivedAt / updatedAt은 실제 수신·갱신 시각이다. 예시 시각·파일 mtime으로 빈칸을 꾸미지 않는다.
- 근거 파일은 verification.evidence, 검증 상태는 pass / fail / not_run / partial, 후속은 nextActions, 대체 관계는 supersedes를 활용한다.
- 신원·수신 시각이 확인되지 않으면 발명해서 형식을 완성하지 않는다. 미확인·등록 대기로 구분하고 확인 후 기존 형식으로 기록한다.
- 실제 변화·결정·결과·중단 인수인계가 있을 때 갱신한다. 같은 요청은 원글 댓글과 revision으로 이어 간다.
- 다른 AI의 수신·읽음·적용/ACK를 대필하지 않는다. 과거 2천여 기록을 가짜 새 날짜·새 형식으로 일괄 변환하지 않는다.

## 보관·정리·공개
낡거나 대체된 내용은 현재본에서 빼고 날짜 보관함과 대체 현행 링크로 연결한다.
나이만으로 원본·사용법·이미지·백업·미저장 자료를 자동 삭제하지 않는다.
동일 해시 중복이나 다시 만들 수 있는 자체 임시 찌꺼기만 참조 여부를 확인한 뒤 승인 범위에서 정리한다.
자격증명은 보관본이라도 공개하지 않는다. GitHub에는 승인된 선별 설명·예제·비민감 이미지·정책만 올린다.
대화 원문·토큰·계정 설정·DB·개인 첨부·모델 파일은 제외한다. 로컬 수집과 명시적인 일회 GitHub 전송은 별개다.

## 작성 예시 — 실제 작업·수신 기록 아님
- 분류·제목: [사용법] 예시 도구의 이미지 질문
- 대상·용도: 예시 도구로 설명과 그림을 함께 확인하는 방법
- 작성자·작성/수신 시각: 실제 확인한 값을 사용해야 하며 이 예시에는 가상 신원·사건 시각을 넣지 않음
- 원문 발행일·촬영일: 미상
- 설명: 관련 대상 폴더에 원래 설명·이미지·설정 예제·라이선스를 함께 보관하고 여는 방법을 짧게 적음
- AI 평가: 설명 초안의 의견이며 도구 실행·품질은 아직 미검증
- 확인 상태·관련 파일: 작성 예시 / 실제 검증 파일 없음
- 현재본·이전본·다음 행동: 안정된 현재 파일로 연결하고 이전본은 보관 링크, 다음은 실제 실행 확인
