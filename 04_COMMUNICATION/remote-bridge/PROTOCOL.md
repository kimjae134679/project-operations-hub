# 공용 PC 연결 규약의 입구

관리 앱·로컬 도구·원격 GPT는 같은 작업 규약과 기기 ID를 사용합니다. 전송 통로가 달라도 작업 식별자·프로젝트·요청 도구·의존 관계·자원 충돌·실제 결과를 유지합니다.

| 구분 | 기준 |
|---|---|
| 현재 소스 규약 | [ProjectBridge 3.0 공통 규약](releases/20261006-v3/UNIVERSAL_PROTOCOL.md) |
| 기존 설치와 호환 확인 | [ProjectBridge 2.0 규약](releases/20261006-v2/UNIVERSAL_PROTOCOL.md). 실제 PC 3.0 설치 확인 전까지 소스와 설치 버전을 혼동하지 않음 |
| PC 안의 공통 연결 | 인증된 `127.0.0.1` 로컬 API와 이를 사용하는 MCP 어댑터. GitHub 통과 없이 같은 PC 서비스에 작업 제출 |
| 원격 요청 | 인증된 도구가 접근 가능한 비공개 `remote/pc-bridge` 중계. 임의의 GPT 대화에 접근 권한을 부여하지 않음 |
| 연결 증거 | 설치 파일 존재와 별도로 실제 장치·최근 응답·인증된 상태·작업 결과를 확인 |
| 작업 분리 | 프로젝트와 명령을 내리는 주체별로 작업 공간·실행 기록·상태 분리. 작업 식별자로 결과와 실행기 내부 단계 대조 |
| 병렬 실행 | 독립 작업 병렬, 실제 겹치는 파일·공유 자원·프로세스·화면만 순서 조정. 공유 자원과 선행 작업 명시 |
| 사용자 화면 | 작업과 상태 확인은 관리 앱 내부. 실행을 위해 별도 명령·작업 창을 띄우거나 포커스를 가져가지 않음 |
| 파일 정리 | 실행 파일·안내는 사용자 입구, 내부 실행·검사·빌드·로그·임시는 전용 폴더. 기존 설정·상태·백업·제작 자료 보존 |
| 공개 기록 | 실제 상세 명령·원문·로그·화면·인증값을 제외한 작업 종류·검증·남은 일 |
| AI 공지 확인 | 각 AI가 본인 프로젝트·세션에서 직접 읽고 기록. 사용자 읽음·자료 수집·전송 성공과 별개 |

로컬 endpoint 파일에는 비밀 인증값이 있으므로 내용을 공개하거나 채팅에 붙이지 않습니다. 작업이 길면 등록된 작업 식별자로 상태를 조회하며, 중계 게시 실패를 이유로 실제 작업을 다시 실행하지 않습니다. 소유권이 확인되지 않은 외부 제작 프로세스는 임의 종료하지 않습니다.

설치 구조의 현재 소스 계약은 다음과 같습니다. 실제 설치 완료와는 별도로 확인합니다.

| 위치 | 역할과 처리 |
|---|---|
| 설치 루트 `프로젝트연결.exe`, `프로젝트_사용안내.md` | 보이는 사용자 실행 입구·안내 |
| `Runtime` | worker·MCP·helper·소스·검사·manifest를 모은 숨김 내부 폴더 |
| 기존 루트 `config.json`, `state` | 기존 경로를 그대로 유지하고 숨김 표시. 실제 기기 설정·진행 기록·활성 ticket 보존 |
| 검증된 이전 배포 파일 | 기존 배포 SHA와 같을 때만 정리. 사용자가 편집했거나 출처 미확인인 파일은 보존 |

MCP의 스크립트 경로는 `D:\A_KJ\AI\Applications\ProjectBridge\Runtime\bridge_mcp.py`이며 `--home D:\A_KJ\AI\Applications\ProjectBridge`는 그대로입니다. 기존 설정을 Runtime 안으로 옮기거나 활성 ticket의 경로를 바꾸지 않습니다. Python 실행 파일은 설치된 config의 실제 경로를 사용합니다.

현재 구현 계약은 `projectId` + `toolId`로 프로젝트와 명령 주체를 구분하고, 전역 유일한 작업 `id`로 각 명령·결과·실행 단계를 대조합니다. `toolId`는 실제 명령 주체별 ID입니다. 같은 제품을 쓰는 독립 주체도 `Codex-audiobook`, `Codex-manager`처럼 다른 ID를 사용합니다. 재시작 뒤에도 같은 공간을 이어 쓰려면 로컬 MCP에 `--issuer <주체ID>`를 명시합니다. 이전 `--tool-id`는 호환 별칭입니다.

주체 설정을 생략한 MCP는 해당 연결에 고유한 `mcp-<UUID>`를 만들어 다른 연결과 기본 ID를 공유하지 않습니다. `pc_status`의 `callerToolId`로 확인하며 `pc_submit`의 선택 `toolId`로 요청별 주체를 명시할 수도 있습니다. 새 로컬 HTTP 요청은 `toolId`가 필수이며 새 원격 AI 요청에도 실제 `projectId`와 고유 주체 `toolId`를 넣습니다. 기존 2.0 비공개 큐만 `ProjectBridge` 호환 기본값을 유지합니다. 이는 새 독립 주체를 합치는 ID가 아닙니다. 이 동작은 소스에서 확인했으며 실제 PC 배포는 별도로 검증합니다.

작업 공간은 `state/workspaces/<프로젝트ID 해시 앞16자리>/<주체ID 해시 앞16자리>`, 해당 주체의 비공개 실행·출력·백업·저널은 `state/general/actors/<프로젝트해시>/<주체해시>`에 분리합니다. 명령에 작업 폴더를 생략하면 자신의 작업 공간을 사용하고 명시적 폴더를 지정할 수도 있습니다. 실제 같은 파일·작업 폴더·프로세스·화면 자원은 충돌 키로 순서를 조정합니다. 이 계약의 구현·검사는 진행 중이며 실제 PC 적용 성공을 대신하지 않습니다.

404는 주소·저장소 접근·브랜치·파일의 어느 단계에서 발생했는지 구분합니다. 이번 기존 2.0 오류는 저장소 메타데이터 API의 불필요한 마지막 `/`였으며, 같은 인증으로 수정된 주소와 실제 장치 왕복을 확인했습니다. 새 설치·다른 장치의 404 원인도 같다고 단정하지 않습니다.
