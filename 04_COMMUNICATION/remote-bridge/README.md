# 프로젝트 연결 — 여러 도구가 함께 쓰는 PC 연결

오디오북·게임·다운로더를 비롯한 여러 프로젝트에서 파일 확인·수정, 설치·빌드, 프로그램 실행, 장기 작업과 화면 조작을 같은 PC 연결로 요청합니다. 관리 앱의 **도구·연결 → 공용 PC 연결**에서 설치·복구, 연결 켜기·일시정지·끄기와 작업 목록을 관리하도록 통합했습니다.

## 같은 연결을 사용하는 방법

| 요청하는 곳 | 작업 통로 | GitHub의 역할 |
|---|---|---|
| 관리 앱과 PC 안의 도구 | 같은 인증된 로컬 API | 파일 작업마다 GitHub를 거치지 않음 |
| MCP를 지원하는 로컬 도구 | 같은 서비스의 stdio MCP 어댑터 | 도구 설정에 어댑터를 연결한 뒤 PC에서 작업 |
| 원격 GPT | 지원되는 비공개 GitHub 중계 | 현재 외부 요청·결과를 전달하는 통로 |

로컬 작업 서비스와 원격 중계의 상태를 따로 표시합니다. GitHub 중계가 끊겼다고 PC 안의 로컬 서비스도 끊겼다고 판단하지 않습니다. Git 작업도 필요한 프로젝트에서 PC의 기존 인증으로 요청할 수 있습니다. 모든 GPT나 도구에 연결 권한이 자동으로 생기는 것은 아니므로 해당 도구가 지원하는 MCP 설정 또는 인증된 원격 통로가 필요합니다.

서로 다른 프로젝트의 독립 작업은 기본 4개 worker에서 병렬 처리합니다. 같은 프로젝트의 수정·명령, 같은 파일·프로세스, 화면 조작은 충돌을 막기 위해 순서대로 처리합니다. 선행 작업과 공유 자원은 요청에 명시하며, 완료 요청을 재전송해도 같은 작업을 중복 실행하지 않습니다. 긴 작업은 등록된 작업 식별자로 진행을 확인하고 해당 연결이 소유한 작업만 중지합니다.

## 자료와 작업 보호

원격 중계는 비공개 `kimjae134679/Mushoku-Tensei-AI-Audiobook`의 `remote/pc-bridge` 브랜치에서 `_pc_bridge/queue.json`, `_pc_bridge/devices`, `_pc_bridge/results`를 사용합니다. 저장소 이름은 작업 범위를 오디오북으로 제한하지 않습니다.

실제 명령·파일 내용·로그·화면·개인 자료와 인증값은 로컬 또는 비공개 통로에 둡니다. 공개 통합소통에는 작업 종류·검증 결과·남은 일만 요약합니다. 토큰을 채팅이나 공개 저장소에 올리지 않습니다. 기존 gh/git 인증을 사용하며 새 모델 API 결제는 필요하지 않습니다.

바탕화면에는 파일을 만들거나 변경하지 않습니다. 관리 앱에서 숨김 설치·로그인 시작을 처리하며 불필요한 CMD·PowerShell 창을 띄우지 않습니다. 프로그램을 닫는 것, 연결을 일시정지하는 것과 이번 로그인 동안 연결을 끄는 것은 구분합니다. 제작 상태를 확인하기 전에 오디오북 큐를 다시 만들거나 실행하지 않습니다.

## 실제 검증 순서

장치 ID·최근 응답 대조 → 기능 조회 → 파일 읽기 → 임시 파일 SHA 조건부 수정 → 짧은 명령 → 화면 캡처 → 테스트 앱 입력 순으로 확인합니다. 새 버전의 로그인 자동 시작, 명시적 끄기와 비정상 종료 복구는 실제 PC에서 별도로 검사합니다. Windows 잠금·UAC 보안 화면은 해당 사용자 세션의 제약을 따릅니다.
