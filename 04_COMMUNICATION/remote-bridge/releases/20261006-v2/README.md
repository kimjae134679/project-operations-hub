# 프로젝트 연결 2.0 — 공용 PC 연결

하나의 Windows 연결 프로그램으로 여러 프로젝트의 파일 수정·명령 실행·설치·빌드·장기 작업·화면 확인과 입력을 요청합니다. 프로그램은 D:/A_KJ/AI/Applications/ProjectBridge/프로젝트연결.exe입니다. Windows 로그인 후 창 없는 작업 자식과 트레이로 시작하며, 바탕화면에는 파일을 만들지 않습니다.

실제 PC 최초 설치·인증·화면 동작은 확인 전입니다. 공개 허브의 설치 안내에 있는 명령을 한 번 실행합니다. 설치 코드·프로그램 소스의 고정 commit 및 SHA를 확인하고 Windows에서 네이티브 실행기와 화면 helper를 만듭니다. 순수 x86/x64 입력 ABI 검사는 설치 중 실행하며 실제 입력을 주입하지 않습니다.

[사용 안내](프로젝트_사용안내.md) · [다른 GPT/프로젝트가 사용할 작업 규약](UNIVERSAL_PROTOCOL.md)

## 연결과 자료

- 공개 배포·안내·짧은 실행 요약: kimjae134679/project-operations-hub, 04_COMMUNICATION/remote-bridge
- 상세 작업 요청·명령·출력·화면: 비공개 kimjae134679/Mushoku-Tensei-AI-Audiobook의 remote/pc-bridge branch
- 로컬 기록·백업·장기 작업: 설치 폴더의 state
- 프로젝트 원본·자료는 각자의 기존 위치에 유지합니다.

현재 사용할 수 있는 비공개 저장소의 이름에 무직전생이 들어가도 원격 범위는 모든 프로젝트입니다. GitHub 연결로 비공개 채널을 읽고 쓸 수 있는 대화에서 사용합니다. 새 PC는 실제 장치 기록의 ID를 확인한 뒤 지정하며 잘못된 장치·만료·같은 ID의 내용 변경을 실행하지 않습니다. 비공개 저장소인지 매번 확인하고 공개 상태이면 공용 원격 작업을 막습니다. 공개 허브에는 명령·stdout/stderr·파일 내용·화면을 보내지 않습니다. 자격증명은 기존 PC의 gh/git 로그인에서 읽으며 결과에 넣지 않습니다.

PC가 켜져 있고 연결이 실행 중이면 요청을 받아 처리합니다. 연결은 GPT 모델을 자동 호출하지 않으며 이 프로그램에 OpenAI API 키는 필요하지 않습니다. 대화가 끝나도 이미 시작한 로컬 장기 작업은 진행할 수 있습니다. 새 판단·새 지시를 GPT 없이 스스로 만드는 프로그램은 아닙니다.

## 사용과 복구

연결 / 재개로 요청을 받습니다. 연결 일시정지는 새 요청만 멈추고, 연결 종료는 현재 동기 작업 뒤 종료합니다. 같은 로그인 동안 자동 재시작하지 않고 다음 로그인에 재개합니다. X는 트레이로 접습니다. 다른 Python·편집기·기존 원격 서비스는 종료하지 않습니다. PC 종료·절전·UAC 보안 화면·관리자 권한은 실제 환경의 제약을 따릅니다.

완료 작업의 업로드만 실패하면 결과 전송을 재시도합니다. 충돌 중 실행 여부가 모호하면 interrupted로 남기며 무조건 재실행하지 않습니다. 파일 수정은 기존 SHA와 백업을 확인합니다. 장기 작업은 별도 UUID 소유 ticket으로 조회·중지하며 임의 PID·프로세스 이름으로 전체 종료하지 않습니다. 정상 종료한 명령의 자식 GUI·서비스는 유지하고 명시적 중지·시간 초과·비정상 종료 때 해당 작업의 소유 자식만 정리합니다.

원격 명령은 사용자가 요청한 작업 범위에서 실행합니다. 바탕화면 변경·미저장 파일 덮어쓰기·기존 작업의 광범위 종료·불필요한 관리자 요청을 피합니다. 관리자 권한이나 잠긴 화면을 자동으로 우회하는 기능은 없습니다.

## 오디오북을 함께 사용

기존 D:/AI/VoiceAudiobook이 존재하면 기존 오디오북용 허브 큐와 로컬 청취 평가 서버도 별도로 켭니다. 공용 요청 루프는 별도 스레드이므로 음성 비교 생성이 길어도 다른 PC 요청을 받을 수 있습니다. 기존 본편 controller나 배역 설정을 설치만으로 중복 실행·교체하지 않습니다. 최초 승인된 청취 코드 bundle의 SHA와 기존 파일 SHA를 확인하고 백업 후 적용합니다.

## 검사

python -m unittest discover -s tests -v

Linux 검사는 파일 보호·장치 선택·자료 공개 차단·업로드 재시도·프로세스 결과·화면 요청 형식 등을 확인합니다. Windows 컴파일·PID 생성 시각·실제 화면 입력을 Linux 검사 통과로 대신하지 않습니다. 설치와 실제 원격 왕복을 확인한 뒤 결과를 갱신합니다.
