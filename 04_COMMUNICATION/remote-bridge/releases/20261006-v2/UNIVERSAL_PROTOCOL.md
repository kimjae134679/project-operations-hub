# ProjectBridge · 공통 PC 작업 연결

이 문서는 한 PC의 여러 프로젝트를 같은 연결 프로그램으로 다루는 운영 계약입니다. 프로젝트별 작업 파일과 배역·대본·모델은 각각의 기존 위치에 둡니다. 무직전생용 작업은 일반 PC 작업과 함께 사용할 수 있지만, 새 연결을 설치했다는 이유로 이미 실행 중인 제작 큐를 다시 시작하지 않습니다.

## 두 저장소의 역할

| 연결 | 위치 | 담는 내용 |
| --- | --- | --- |
| 배포·사람용 안내 | 공개 `kimjae134679/project-operations-hub` | 연결 프로그램의 소스, 설치 안내, 검증 범위, 공개해도 되는 짧은 작업 결과 |
| 실제 PC 작업 | 비공개 `kimjae134679/Mushoku-Tensei-AI-Audiobook`의 `remote/pc-bridge` branch | 작업 요청, 실제 명령 인수, 파일 작업 내용, 상세 결과와 화면 자료 |
| 실제 프로그램·자료 | 사용자 PC | 각 프로젝트 원본, 실행 프로그램, 작업 로그, 백업, 음원과 모델 |

비공개 저장소의 이름은 현재 사용할 수 있는 저장소 이름이며 작업 대상을 무직전생으로 제한하지 않습니다. 별도 branch의 PC 작업 공간을 사용합니다. branch를 구성했다고 프로젝트 소스 branch나 PC 설치본이 변경된 것은 아닙니다. GitHub를 사용할 수 있는 다른 대화도 이 비공개 저장소에 접근할 권한이 있어야 작업을 요청하거나 결과를 읽을 수 있습니다.

공개 허브에는 명령 전문, stdout/stderr, 로컬 파일 내용, 대사, 소설 원문, 표본 음성, 영상, 모델, 화면 캡처, 자격증명을 올리지 않습니다. 비공개 채널도 자격증명을 기록하는 장소로 사용하지 않습니다. 토큰은 PC의 기존 GitHub 인증에서 읽고 출력·결과·설치 안내에 넣지 않습니다.

## 큐 계약

요청 파일은 비공개 branch의 `_pc_bridge/queue.json`입니다.

```json
{
  "schemaVersion": 1,
  "jobs": []
}
```

각 job의 필드는 다음과 같습니다. 실행 가능한 `action`과 `args`의 정확한 조합은 배포된 worker가 검증합니다. 알 수 없는 action을 비슷한 명령으로 추정해 실행하지 않습니다.

| 필드 | 의미 |
| --- | --- |
| `id` | 요청마다 새로 만드는 유일한 작업 ID |
| `action` | 배포된 worker가 지원하는 동작 이름 |
| `args` | 해당 동작의 JSON 인수 객체 |
| `createdAt` | 요청을 실제 만든 시간대 포함 ISO 시각 |
| `expiresAt` | 요청을 더 이상 시작하지 않을 시간대 포함 ISO 시각 |
| `target` | 공통 PC 요청에는 필수로 `PC`를 사용. 기존 오디오북 전용 작업은 별도 계약을 사용 |
| `deviceId` | 필수 PC 선택 값. 실제 장치 기록에서 발견한 정확한 ID를 사용하며 이름으로 추정하지 않음 |
| `projectId` | 선택적인 통합소통 프로젝트 slug. 생략하면 `Control-Tower` |
| `dependsOn` | 선행 성공이 필요한 작업 ID 배열. 선택 필드 |

장치 목록은 `_pc_bridge/devices/<device>.json`에 있습니다. 실제 마지막 연결 시각과 제공 가능한 기능을 먼저 확인하고 요청의 `deviceId`를 지정합니다. 이 파일에는 비밀값이 포함되지 않아야 합니다. 과거 장치 기록의 존재만으로 PC가 지금 연결됐다고 판단하지 않습니다.

지원 동작의 구체적인 인수:

| `action` | `args` |
| --- | --- |
| `capabilities` | `{}`. 실제 연결 장치의 지원 기능 확인 |
| `read_file` | `path`, 선택 `maxBytes`(최대512KiB)·`offsetBytes` |
| `write_file` | `path`, `expectedSha256`(`null` 또는 SHA-256), `contentUtf8` 또는 `contentBase64` 중 하나 |
| `list_dir` | `path`, 선택 `limit` |
| `run_command` | `cwd`, `argv` 배열 또는 `powershell` 문자열 또는 `python` 문자열 중 하나, 선택 `timeoutSeconds` |
| `start_process` | 명령 표현·작업 폴더는 `run_command`와 같음. 비동기 실행의 소유 ticket 반환 |
| `process_status` | `processId`: 해당 worker가 발급한 UUID ticket |
| `stop_process` | `processId`: 해당 worker가 발급한 UUID ticket |
| `ui_control` | `action`과 해당 화면 helper의 `args` 객체 |

`ui_control.action`은 `screen_capture`, `window_list`, `mouse_click`, `mouse_scroll`, `type_text`, `send_keys`, `focus_window`를 지원합니다. 구체적 좌표·문자·키·창 선택 인수는 같은 배포본의 화면 helper 정의를 확인합니다. 결과는 helper가 실제 반환한 JSON을 사용합니다. 별도 프로그램의 PID를 소유 ticket인 것처럼 넣지 않습니다.

요청을 추가할 때는 현재 큐를 읽고 기존 요청을 보존합니다. 현재 branch commit을 기준으로 변경하며, 다른 작업자가 먼저 갱신한 경우 최신 큐를 다시 읽고 합칩니다. 남의 요청을 없애거나 branch를 강제 덮어쓰지 않습니다.

동일 ID의 완료 작업은 결과 전송 재시도만 수행합니다. 같은 ID로 내용만 바꾸어 다시 실행하지 않습니다. 재실행이 필요하면 실패 원인을 확인하고 새 ID로 요청합니다. 만료·미래 시각·잘못된 인수·실패한 의존 작업은 성공으로 표시하지 않습니다. 연결 중단 뒤 실행 여부가 불확실한 작업은 결과와 로컬 기록을 먼저 확인하며, 파일 변경·설치 같은 작업을 무조건 재실행하지 않습니다.

## 결과 계약

실제 작업 결과는 비공개 branch의 `_pc_bridge/results/<device>/<job>.json`에 저장합니다. 결과 필드는 `schemaVersion: 1`, `device`, `jobId`, `jobSha256`, `finishedAt`, `outcome`, `data`입니다. 요청의 ID·hash·장치와 실제 결과가 일치하는지 확인합니다. action별 `data`는 같은 배포본의 worker 및 테스트를 기준으로 합니다. 작업 등록, 프로세스 시작, 종료 코드, 산출물 검증, 사용자 흐름 검증을 따로 판단합니다.

- GitHub 기록이 있다는 것만으로 PC 작업을 완료로 판단하지 않습니다.
- 프로세스를 시작한 결과는 해당 빌드·설치·음원 제작의 완료 결과가 아닙니다.
- screenshot이 반환됐으면 실제 화면을 읽고 판단합니다. 화면 파일 생성만으로 UI가 정상이라고 승인하지 않습니다.
- 결과 업로드 실패는 로컬 실행 실패와 구분합니다. 이미 끝난 작업을 다시 실행해 결과를 만들지 않습니다.
- 결과에 실패·권한 부족·연결 대기가 있으면 그대로 남기고 다음에 필요한 행동을 적습니다.

## 공통 작업 범위

| 범주 | 활용 | 실제 제약 |
| --- | --- | --- |
| 파일·폴더 | 목록·내용 확인, 수정, 정리, 복사, 백업 | 로컬 사용자 권한과 worker의 경로·인수 검사를 따름. 기존 수정·원본을 보호 |
| 명령·빌드·설치 | 명시한 실행 파일과 인수로 작업하고 결과 확인 | 권한·의존성·실행 파일 존재·종료 코드 확인 필요. 관리자 승인 자동 통과 없음 |
| 프로그램·프로세스 | 실행·상태 확인·작업 결과 확인 | 이미 실행 중인 외부 작업은 소유권 없이 일괄 종료하지 않음 |
| 화면·입력 | Windows 화면 확인과 지원되는 입력 동작 | 실제 로그인된 대화형 화면 필요. 잠금 화면·UAC 보안 화면·관리자 앱은 제한될 수 있음 |
| 프로젝트 자동화 | 기존 제작·수집·검사 스크립트 실행 | 프로젝트별 규칙·사용 안내·현재 큐와 실행 상태 확인. 연결과 업무 완료는 별개 |

지원 범주는 실행 환경 전체를 무제한으로 제어한다는 뜻이 아닙니다. 실제 action 구현과 Windows에서 확인한 기능 범위를 사용합니다. Desktop Commander 서비스와 새 연결은 별도 프로그램입니다. 새 연결을 켜거나 닫는다고 기존 원격 서비스·편집기·오디오북 제작 작업을 임의 종료하지 않습니다.

## PC 설치·로그인 실행

프로그램 목표 위치는 `D:\A_KJ\AI\Applications\ProjectBridge\프로젝트연결.exe`입니다. 공개 배포본의 정확한 commit과 manifest SHA를 확인해 최초 설치를 한 번 수행합니다. [공개 설치 코드](https://github.com/kimjae134679/project-operations-hub/blob/main/04_COMMUNICATION/remote-bridge/install.ps1)와 같은 배포본의 [README](README.md)를 따릅니다. 설치에 사용되는 `releases/20261006-v2` 자료도 정확한 배포 commit으로 고정합니다. 설치 코드를 작성하거나 Linux 테스트를 통과한 상태를 실제 Windows 설치 완료로 기록하지 않습니다.

`-StartAtLogin`으로 등록하는 `ProjectBridge_Login`은 이 프로그램 전용입니다. 같은 이름의 기존 등록이 다른 프로그램을 가리키면 덮어쓰지 않습니다. 등록을 할 수 없는 경우에는 안내된 현재 사용자 로그인 진입점을 사용하며 바탕화면에 파일을 만들지 않습니다. 설치·자동 시작 결과는 실제 PC에서 확인합니다.

로그인 자동 실행은 숨김 실행을 사용합니다. 의도적으로 연결을 종료한 경우에는 같은 로그인 중 다시 켜지지 않으며, 다음 로그인에는 다시 시작합니다. Windows 종료·로그오프 중에는 다시 시작하지 않습니다. 새 연결의 감시·복구는 자신의 worker만 대상으로 하며, 종료를 숨기기 위해 PC 전체 프로그램을 강제 종료하지 않습니다. PC 종료·절전·네트워크 단절 중에는 요청이 처리되지 않을 수 있습니다.

## 통합소통 기록

통합소통은 비공개 PC 결과를 대신하는 실행 채널이 아닙니다. 공통 PC 작업의 공개 운영 상태와 표준 task_exchange에는 `action`과 `outcome`만 추려 기록합니다. 명령, argv, 작업 대상 파일명, 출력, 이미지, 실제 파일 내용은 공개 결과로 옮기지 않습니다. 별도 오디오북 전용 결과 계약과 일반 PC 작업의 공개 범위를 섞지 않습니다.

표준 `task_exchange`의 원본 스키마는 허브 `05_TEMPLATES/TASK_EXCHANGE.schema.json`입니다. 본인이 받은 실제 지시와 전달한 답변을 기록하고 revision을 올리며, 같은 지시의 수신 시각을 보존합니다. 프로그램이 만든 실행 기록과 AI 본인의 읽음·적용 기록은 구분합니다. 다른 AI가 내용을 읽었다고 대신 기록하지 않습니다.

공지 N-0008 r2는 프로젝트별 `프로젝트_사용안내.md`를 진입점으로 사용하고, N-0009 r1은 숨김 로그인 실행과 종료 방해 방지를 요구합니다. 실제 로컬 기록 작성, 앱 수집, 중앙 공개, 다른 AI의 확인은 각각 다른 상태입니다. 공개 GitHub에서 읽은 내용을 실제 PC에서 배포·적용했다고 표시하지 않습니다.

## 검증과 남은 범위

이 문서는 운영 계약과 연결 위치를 설명합니다. 현재 제공 가능한 검증은 해당 배포본의 소스·자동 테스트 결과를 기준으로 합니다. 실제 Windows 설치·로그인 자동 시작·외부 연결 왕복·파일 변경·화면 입력·UAC·잠금 화면·전 프로젝트 사용자 흐름은 각각 실행 근거가 확인되기 전까지 미검증입니다.

재개할 때는 이 문서, 실제 프로젝트의 사용 안내, worker 버전, 연결 결과, 현재 작업 큐 순서로 확인합니다. 기존 무직전생 제작 작업이 살아 있으면 상태를 관찰하고 필요한 청취 목록·QA를 갱신하며, 동일 제작 큐를 중복으로 시작하지 않습니다.

## 화면 helper 인수

- screen_capture: primary?, crop?{x,y,width,height}, maxWidth(320~1920), maxHeight(240~2160), quality(20~85). JPEG와 실제 virtual_bounds/capture_bounds 및 scale_x/scale_y를 반환합니다.
- window_list: limit(1~200). 반환한 hwnd·PID·제목을 확인합니다.
- mouse_click: 실제 데스크톱 픽셀 x,y, button(left/right/middle), clicks(1/2).
- mouse_scroll: amount(-120~120 wheel notch), horizontal?.
- type_text: text(최대4000 UTF16단위). 클립보드 변경 없이 Unicode 입력합니다.
- send_keys: keys 문자열, 예 CTRL+S / ENTER / ALT+F4 / ESC.
- focus_window: window_list가 반환한 hwnd의 10진 문자열.

축소 이미지를 본 좌표는 실제 데스크톱 좌표로 변환한 뒤 클릭합니다. 화면이 잠겼거나 UAC/다른권한으로 입력이 차단되면 실제 오류를 따르고 우회하지 않습니다. 순수 요청/ABI 검사는 실제 화면 확인·입력 완료와 구분합니다.
