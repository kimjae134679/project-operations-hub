# ProjectBridge 3.2.2

작성일: 2026-11-18 KST. 3.2.0 설치본의 전송·UIA·작업 관리 기능과 기존 3.0의 장기 작업/충돌 보완을 합친 유지보수판이다.
설치·운영 확인은 [VALIDATION.json](VALIDATION.json), 기본 사용은 [프로젝트_사용안내.md](프로젝트_사용안내.md)를 따른다.

변경:
- 창 활성화 실패를 foreground_activation_denied로 분리. 오류 details는 창 전환 범위·예상/관측 hwnd·자동 반복 금지·다른 PC 작업 가능 여부를 반환한다.
- SetForegroundWindow는 한 번만 호출하고 실제 상태를 최대 400ms 관측한다. 권한 우회·강제 포커스 API를 추가하지 않았다.
- 전경 창 변경 시 입력 전 중지·목록 새로 확인을 안내한다. host 거절과 OS 창 전환 실패를 혼동하지 않는다.
- 시작 접수와 실제 종료를 분리하고 의존 관계·실행 자원을 종료까지 유지한다. 기존 작업은 복구 시 상태만 조회한다.
- 과거 접수/완료 결과의 정확한 충돌만 격리하고 다른 비공개 중계 처리를 계속한다. 인증·네트워크·알 수 없는 충돌은 성공으로 바꾸지 않는다.
- 반복 공개 기록 게시와 구형 공개 큐의 자동 실행을 중단한다. 기존 private PC 연결은 유지한다.
- 최근 20개 항목을 유지하고 오래된 큰 완료 기록은 담당자별 원문을 해시 검증해 색인으로 참조한다. 시작 시 원문을 다시 쓰지 않고, 결과 조회는 원문을 복원해 반환한다.
- 버전은 version.py 한 곳에서 제공한다. 원자적 임시 파일과 새 백업 이름을 짧게 만들어 Windows 경로 제한에 걸리던 오류를 줄인다. 이전 백업 경로는 그대로 보존한다.

## 설치본 업데이트

새 설치를 위한 구버전 install.ps1을 실행하지 않는다. 이미 연결된 본체를 대상으로 현재 Python으로 아래 도구를 사용한다.

```
python update_installed.py --home <기존 설치 폴더>
python update_installed.py --home <기존 설치 폴더> --apply
```

첫 명령은 점검·계획만 출력한다. --apply는 manifest 검사·컴파일·유휴 재확인·백업 후 기존 실행기의 정상 종료/백그라운드 재개를 사용한다.
config·ACL·로그인 작업·기기 ID는 보존한다. 이전 파일은 state/install-backups 아래에 복원 대응표와 함께 보존한다.
새 MCP 도구 설명은 어댑터를 다시 연결한 세션에서 읽힌다. 이미 열린 다른 채팅의 도구 목록을 강제로 바꾸지 않는다.

## 검사

현재 Python에서 release 폴더를 PYTHONPATH에 추가하고 unittest discover -s tests를 실행한다.
tests/test_universal_actions.py의 구형 설치기 설정 검사는 형제 20261006-v3/install.ps1을 역사적 fixture로 읽는다.
그 설치기는 3.2.2 배포기가 아니다. UI 테스트는 자체 화면 밖 테스트 폼과 입력 전 거절만 확인하며 실제 Chrome 업로드 성공을 뜻하지 않는다.
