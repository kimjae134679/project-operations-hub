# ProjectBridge 3.0 — 공용 PC 연결

통합 관리 프로그램에서 설치·연결 켜기·일시정지·연결 끄기를 사용합니다. GitHub 인증이 실패해도 PC 안의 도구는 인증된 로컬 연결로 작업할 수 있습니다. 원격 ChatGPT는 지원되는 비공개 GitHub 중계를 사용합니다. 연결되지 않은 GPT 서비스에 권한이 자동으로 생기지는 않습니다.

- 설치 경로: `D:\A_KJ\AI\Applications\ProjectBridge`
- 실행 파일: `프로젝트연결.exe` — 콘솔 없는 Windows 프로그램
- 사용자 폴더에는 실행 파일과 `프로젝트_사용안내.md`만 보입니다. 내부 코드·검사·화면 도구는 숨김 `Runtime` 폴더에 모으며, 기존 설정과 작업 기록은 숨김 처리한 원래 경로에 유지합니다.
- 기존 `config.json`의 기기 ID, 프로젝트 위치, Python, 사용자 설정을 유지합니다.
- 기본 병렬 작업 수는 4입니다. 프로젝트와 명령을 보낸 담당자마다 작업 폴더·로그·개별 기록을 분리합니다. 독립 작업은 동시에 처리하고 같은 파일·명령 폴더·화면 입력이 겹치면 순서대로 처리합니다.
- 장기 작업은 시작 접수와 실제 완료를 구분합니다. 실행 중에는 자원 예약과 다음 단계 대기를 유지하고, 실제 성공했을 때만 후속 작업을 진행합니다. 연결 프로그램을 재시작해도 등록된 작업을 중복 실행하지 않고 상태 확인을 이어갑니다.
- 로컬 연결과 원격 GitHub 중계 상태를 구분합니다. 화면의 마지막 응답이 12초 이상 오래되면 응답 없음으로 표시합니다.
- X는 트레이로 숨깁니다. **연결 끄기**는 이번 로그인 동안 중지합니다. 다음 로그인에 다시 시작합니다.
- 시작 시 오디오북 제작 큐를 생성하거나 중복 실행하지 않습니다. 기존 오디오북 전용 작업의 저널을 그대로 사용합니다.

로컬 도구에는 MCP stdio 어댑터 또는 인증된 HTTP API를 연결할 수 있습니다. [공통 규약](UNIVERSAL_PROTOCOL.md)에 설정과 명령을 적었습니다. 모든 도구를 무조건 강제로 변경하지 않고 각각의 MCP 설정에 같은 어댑터를 등록하면 됩니다.

MCP의 `--issuer Codex-audiobook`, `--issuer Codex-manager`처럼 담당자마다 다른 안정적인 ID를 사용합니다(`--tool-id`도 같은 옵션입니다). ID를 지정하지 않으면 연결마다 고유 ID를 발급하여 서로의 작업 폴더를 자동으로 공유하지 않습니다. 실행 창을 새로 띄우거나 화면 포커스를 옮기지 않고 관리 프로그램 안에서 작업 상태를 확인합니다.

통합 관리 프로그램은 내장 릴리스를 임시 설치 폴더에 풀고 다음과 같이 설치합니다. 다운로드나 공개 GitHub 큐를 거치지 않습니다.

```powershell
powershell.exe -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File install.ps1 -SourceDirectory <내장_릴리스_폴더> -StartAtLogin
```

독립 설치는 커밋과 manifest SHA를 고정해 `install.ps1 -Commit <40자리> -ManifestSha256 <64자리> -StartAtLogin`을 사용합니다. 모든 파일 SHA, 네이티브 빌드와 테스트가 통과한 다음 기존 브리지만 교체합니다. 변경된 파일과 실행 파일은 `state/install-backups`에 보존합니다. 바탕화면에는 파일을 만들지 않습니다.

파일 내용·명령·로그·화면은 PC 또는 비공개 저장소에만 보관합니다. 공개 통합소통에는 작업 종류와 성공 여부만 남깁니다. 인증 토큰은 결과나 공개 기록에 넣지 않습니다.

개발 환경에서 검사와 빌드가 완료된 것과 사용자 PC에서 설치·자동 시작·원격 왕복이 검증된 것은 구분해서 기록해야 합니다. 설치 성공만으로 원격 연결 성공이라고 표시하지 않습니다.

설치 사전 검사는 기존 `config.json`에 Hidden 또는 System 속성이 있으면 `config_writealltext_attribute_conflict_before_install`과 해당 속성을 표시하고 브리지 중지·설치 파일 교체 전에 중단합니다. 읽기·쓰기 접근 검사가 통과해도 이후 `WriteAllText`의 생성·잘라쓰기 동작은 이 속성 때문에 거부될 수 있습니다. 설정 내용·속성·ACL을 변경하거나 자동으로 권한을 우회하지 않습니다. 이 소스 방어와 검사 통과는 운영 설치 완료 또는 과거 실패 원인 확정을 뜻하지 않습니다.

장기 작업 저널의 `monitoring`은 별도 실행 중인 등록 작업의 확인을 이어가는 상태입니다. 최초 시작 접수는 `acceptedResult`에 보존하며 `result`와 로컬 결과 파일은 현재 상태·실제 종료 결과를 기록합니다. 시작 접수만으로 비공개 중계 결과나 공개 성공 기록을 게시하지 않습니다. 상세 동작과 유지보수 제한은 [공통 규약](UNIVERSAL_PROTOCOL.md)을 따릅니다.
