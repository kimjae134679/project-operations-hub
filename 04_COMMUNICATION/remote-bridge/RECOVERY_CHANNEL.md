# 작업용 원격과 독립 복구용 원격

상태: 2026-10-07 사용자 지시를 반영한 구현 기준. 복구용 원격은 아직 설치·실행되지 않았다.

사용자는 작업용 원격이 고장 나거나 업데이트 중 중단되어도 별도 원격으로 수리할 수 있도록 두 경로를 유지하도록 요청했다. 기존 Desktop Commander는 유지한다. 사용 한도로 정지된 연결을 정상 복구 경로라고 보고하지 않는다.

| 항목 | 작업용 | 복구용 |
|---|---|---|
| 역할 | 프로젝트별 실제 작업 실행 | 작업용 원격 진단, 검증된 설치·복원과 재시작 |
| 실행 파일·런타임 | ProjectBridge 기존 설치 | 별도 설치와 고정된 검증 버전 |
| 설정·상태·기록 | 기존 config/state 및 프로젝트·요청자별 기록 | 별도 config/state/복구 기록, 작업용 설정을 로드하지 않음 |
| 인증·장치 ID | 작업용 채널 | 별도 로컬 인증 토큰과 장치 ID |
| 시작·생존 확인 | 기존 시작 항목과 명령 왕복 | 별도 숨김 시작 항목과 자체 명령 왕복 |
| 비공개 명령·결과 큐 | 기존 작업용 큐 | 별도 복구용 큐와 결과 경로 |
| 업데이트 | 작업용 버전 변경 | 작업용 설치 중 덮어쓰거나 함께 재시작하지 않음 |

두 실행기는 추가 CMD/PowerShell 창 없이 내부에서 실행한다. 사용자가 통합 프로그램에서 두 연결의 온라인 여부와 실제 명령 성공 여부를 구분해서 볼 수 있어야 한다. 복구용은 모델 호출 없이 작동해야 한다. 모델을 사용하는 작업에서는 실제 지원이 확인된 6.1 계열을 우선하고 Astra는 사용하지 않는다.

복구 과정은 대상 파일의 기존 해시와 소유 경로, 파일 속성, 쓰기 가능 여부부터 확인한다. 설정·기존 작업 기록·예약·진행 중 작업을 보존하고, 검증된 백업으로 돌아갈 경로를 먼저 남긴다. 작업용 원격이 멈춰 있는 상태에서 복구용 자체 명령이 실행되는지 확인해야 한다. 작업용 설치 완료는 실제 인증 명령 왕복 성공과 비공개 relay 결과가 확인된 뒤에만 보고한다.

이번 오류는 기존 설치가 숨겨 둔 config.json에 File.WriteAllText를 사용한 업그레이드 경로에서 발생했다. 기존 Hidden 파일을 FileMode.Open으로 저장해 ACL과 속성을 유지하고, 짧은 내용은 SetLength로 잘라낸다. 읽기 전용·비정상 파일·권한 문제는 원격을 중단하기 전 사전 검사에서 차단한다. ACL 변경이나 관리자 실행을 일반 해결책으로 사용하지 않는다.

후속 구현에서는 검증된 복원 파일 목록, 새로 만든 파일의 되돌리기, 기존 중지·시작 상태와 시작 항목 복구를 포함해야 한다. 기존 원격 설정이나 실행 파일에 의존하는 두 번째 인스턴스를 독립 복구용으로 간주하지 않는다.
