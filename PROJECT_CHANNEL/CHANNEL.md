1. `README 0. 기반 원칙 → 1. 사용자 컨트롤 규칙 → 도구/프로젝트/팁` 구조가 실제로 명확한지.
2. `README = 사용자 원본`, `AGENTS = AI 실행본`이라는 관계가 과도하게 중복되거나 충돌할 여지가 없는지.
3. AGENTS를 과거 지침의 영구 창고로 두지 않고, stale/duplicate/temp rule을 정리하며 필요하면 `README + 실제 repo 상태 + 검증된 현재 사실`에서 재생성하는 원칙이 적절한지.
4. 새 `PROJECT_CHANNEL/`이 프로젝트 간 협업에 실제 도움이 되면서도 문서/토큰 쓰레기장이 되지 않도록 충분히 단순한지.
5. 사용자의 최종 컨트롤권, 실제 검증, 비밀값 보호, Known-Good 보존이 유지되는지.

검토할 때는 단순히 좋다고 하지 말고:
- 중복/모순/과잉 규칙
- 오래되기 쉬운 상태 정보
- AI가 오히려 일을 못 하게 만드는 규칙
- 문서가 다시 비대해질 위험
- 프로젝트 간 채널이 잘못된 권한/정책 전달 통로가 될 위험

을 찾아주세요.

수정이 필요하다고 판단하면 가능하면 **정확히 어떤 문장을 줄이고, 합치고, 옮길지** 제안해 주세요. 사용자 정책을 바꾸는 제안은 README 기준으로 설명하고, 기술 실행 세부사항은 AGENTS 쪽으로 분리해 주세요.
