# External project metadata reader

Reads existing producer/review/provider-result/voice registration files through the installed ControlTower generic `control.status` JSON contract. The desktop shell is unchanged. This is a finite read, without HTTP, provider calls, producer jobs, writes, timers, new credentials, or automatic retries. `project.sources.json` is PC-only and ignored by Git. Use the example only to configure verified local paths; never use its EXAMPLE_ONLY values as real registration.

The control requires the current installed generic external-control reader (locally validated against 0.9.18). This module commit does not publish or rebuild that desktop implementation. Add a status-only program to an existing `project.control.json`; use fixed node executable, arguments `["reader.mjs","project.sources.json"]`, timeout 30, and fields with paths such as `threads.production.generated`, `threads.review.passed`, `threads.buffer.instagramScheduled`, `threads.buffer.threadsScheduled`, `threads.buffer.partialPosts`, `threads.buffer.instagramErrors`, `threads.buffer.threadsErrors`, `voice.edition`, and `voice.registeredReady`. Do not add start/stop/settings actions. Preserve other owner's registration and back it up before an atomic, conflict-checked append.

Producer input is the existing threads-auto-batch-v1 status. Review counts call the owner's pure `reviewHandoffProjection` and invalidate modified approval content. Provider values are stored observations, not a current queue query or scheduling authority. A scheduled response is not a sent post. Pair counts require two platforms with identical output version and valid identical approval fingerprint; they are evidence counts, not atomic delivery. Unknown statuses, platform errors, missing approval basis and unavailable inputs remain separate. The current result file is an explicit dated provider proof; the owner must update its registration when a new canonical proof replaces it.

Voice prefers `audiobooks/library_latest.json` and its verified inside-root reader/status. A registration-only state reports registered ready entries without inventing a total production denominator. Legacy production_active is used only when the latest pointer is absent, never when it is invalid. No process liveness or audio quality is inferred.

Files are bounded and symlink paths refused. Source byte hashes are rechecked before returning, without retry on a racing writer. This module is a reader: atomic writer/resume rules remain with producer/review/uploader owners.

Run local tests with an already installed trusted Upload Studio pure module root in TEST_STUDIO_ROOT: `node --test reader.test.mjs`. Fixtures use temporary directories and include actual source-file changes and the finite CLI boundary. Local evidence: 10 Node tests and 49 existing desktop consumer/progress tests passed; desktop UI pixels and live provider state were not tested. See [handoff contract](../../docs/threads-external-handoff.md) for content/render approval boundaries. Production documents and media remain on the PC.
