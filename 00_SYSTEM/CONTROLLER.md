# Controller

이 문서는 **현재 ChatGPT 프로젝트에서 사용하는 전체 작업 컨트롤러**입니다.

## 적용 범위

- 이 규칙은 현재 프로젝트에서 허브를 통해 다루는 작업에만 적용합니다.
- ChatGPT 계정 전체, 다른 Project, 다른 독립 채팅에 자동으로 적용하지 않습니다.
- 실제 프로젝트 저장소를 수정할 권한은 사용자의 현재 요청에서 판단합니다. 허브에 등록되어 있다는 사실만으로 수정 권한이 생기지 않습니다.
- 허브는 실행 프로그램을 대신하지 않습니다. 실제 코드·데이터·명령·현재 상태는 각 프로젝트 저장소가 원본입니다.

## 판단 우선순위

1. 현재 채팅의 사용자 최신 지시
2. 실제 대상 프로젝트의 현재 저장소 tip과 README/AGENTS
3. `01_CONTROL/USER_POLICIES.md`
4. 이 허브의 `AGENTS.md`
5. `04_COMMUNICATION/`의 과거 기록과 제안

충돌하면 위 순서를 따릅니다. 오래된 인수인계나 요약은 현재 저장소 상태를 덮어쓰지 못합니다.

## 작업 라우팅

| 요청 | 먼저 볼 곳 | 실제 작업 위치 |
|---|---|---|
| 프로젝트 작업 | `01_CONTROL/PROJECT_REGISTRY.md` → `02_PROJECTS/<name>/README.md` | 실제 프로젝트 저장소 |
| 공통 작업 규칙 | `01_CONTROL/USER_POLICIES.md` | 허브 |
| 설치·사용 도구 | `01_CONTROL/TOOLS.md`, `AI_INSTALLATIONS.md` | 허브와 실제 PC |
| 새 도구 조사 | `03_KNOWLEDGE/CANDIDATE_CATALOG/` | 허브 |
| 이전 결정·진행 확인 | 관련 `04_COMMUNICATION/threads/` | 허브 |
| 사용자용 현황 | `000_사용자용/` | 허브 요약 |

## 기본 작업 순서

1. 요청의 대상 프로젝트와 작업 종류를 정합니다.
2. 필요한 원본 문서만 읽습니다.
3. 실제 프로젝트의 현재 상태를 확인합니다.
4. 요청한 범위에서 작업합니다.
5. 변경 영향에 맞는 검증을 수행합니다.
6. 결과와 미검증 범위를 구분해 보고합니다.
7. 장기적으로 남길 정책·상태·인수인계만 허브에 갱신합니다.

## 읽기와 토큰 사용

- 저장소 전체나 긴 스레드를 처음부터 반복해서 읽지 않습니다.
- 기본적으로 진입 문서, 최신 상태, 관련 파일만 읽습니다.
- 과거 흐름이 필요한 경우 검색으로 관련 기록을 좁힌 뒤 읽습니다.
- 전체 연혁 확인이 실제 판단에 필요한 경우에만 순차 기록 전체를 봅니다.
- 같은 사실을 여러 문서와 답변에 반복하지 않습니다.
- 사용자 보고는 결론, 근거, 변경, 검증, 남은 문제만 짧게 정리합니다.

## 상태 원칙

다음 상태를 섞지 않습니다.

- 후보
- 설치됨
- 연결됨
- 실제 채택됨
- 코드 구현됨
- 정적/CI 검증됨
- 로컬 실행 검증됨
- 실제 사용자 흐름 검증됨
- 실기기·외부 서비스 검증됨

확인하지 않은 상태는 `미확인`, 실행하지 않은 검증은 `미실행`, 막힌 작업은 `BLOCKED`로 남깁니다.

## 문서 원칙

- `000_사용자용/`은 짧은 한글 요약입니다.
- `01_CONTROL/`은 정책과 등록부의 원본입니다.
- `02_PROJECTS/`는 실제 프로젝트로 가는 포인터만 유지합니다.
- `03_KNOWLEDGE/`는 재사용 가능한 조사와 경험입니다.
- `04_COMMUNICATION/`은 연속 기록이며 현재 상태의 원본이 아닙니다.
- 변동이 잦은 package 버전, 커밋, 최신 메시지 번호를 프로젝트 포인터에 고정하지 않습니다.
- 내부 원본을 바꾸면 대응되는 사용자용 요약도 같은 작업에서 갱신합니다.
