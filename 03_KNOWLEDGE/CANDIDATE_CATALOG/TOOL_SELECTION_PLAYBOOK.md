1. 완료 조건과 필요한 증거를 먼저 정합니다. 예: 파일 생성, 실행 성공, 실제 버튼 동작, 실기기 결과.
2. 기존 코드·플랫폼 기능·연결된 도구로 끝낼 수 있는지 확인합니다.
3. 누락된 기능에만 Plugin·CLI·Skill·문서 검색·검사기·Jev·병렬 분업을 추가합니다.
4. 설치·초기화·문맥 로딩·로그·재시도·통합 비용까지 비교합니다.
5. 필요한 검증을 통과하고 결과·사용량·남은 제한을 기록합니다.

## 조건부 병렬 분업

| 작업 모양 | 시작 구성 | 통합 방법 |
|---|---|---|
| 짧고 명확한 변경 | 담당자 1명 | 변경과 필요한 검사 수행 |
| 원인 불명 오류 | 코드 탐색 + 재현/로그 확인 | 서로의 근거를 모은 뒤 구현 담당자가 수정 |
| UI 기능 변경 | 레퍼런스/공식 API 확인 + 화면 재현, 구현 담당자 | 필요한 증거를 병렬 수집하고 수정 파일 담당 지정 |
| 큰 기능 | 계약이 정해진 UI/API/자료 처리 등 독립 영역 | 별도 worktree 또는 겹치지 않는 파일, 통합 담당자 지정 |
| 구현 검토 | 구현 diff가 존재한 뒤 독립 검토 | 위험·검증 누락을 근거 경로와 함께 반환 |

하위 작업 2~3개를 시작값으로 사용하되 작업 규모·의존성·현재 한도에 따라 조정합니다. 이 값은 공식 최적값이 아니라 허브 운영 기본값입니다. 구현 전에 모든 검토자를 띄워놓고 반복 대기시키지 않습니다. 동일 파일 동시 수정이나 큰 빌드·GPU 작업의 무제한 병렬화를 피합니다.

작업 전달에는 **목표, 필수 맥락, 관련 경로, 수정 범위, 완료 조건, 반환 형식**을 넣습니다. 전체 채팅 복사 대신 필요한 사실과 원본 경로를 제공합니다. 결과는 결론·근거·변경·검증·남은 문제만 반환하고 원본 로그는 필요할 때 조회합니다.

OpenAI 공식 문서는 읽기 중심 작업과 요약 반환을 권장하며, 비교 가능한 단일 에이전트보다 서브에이전트가 더 많은 토큰을 소비할 수 있음을 명시합니다. 주 대화의 문맥을 줄이는 효과와 전체 실행 사용량은 별도로 측정합니다.

## Jev: 허가와 실행 상태를 분리

사용자는 Jev 사용을 허용했습니다. 최신 사용자 지시가 이전의 비활성 정책보다 우선합니다. Jev를 매번 사용하거나 자동으로 활성화해야 하는 것은 아니며 추가 결제를 허용한 것도 아닙니다.

2026-10-05 PC의 읽기 확인에서 `jev-router 0.2.0`의 upstream이 **gargpratyush/jev-router**임을 확인했습니다. 현재 upstream `master` package는 0.3.0이며 설치본과 동일 버전이 아닙니다. 이름이 유사한 다른 router의 정책·절감 실험 결과를 이 설치본에 적용하지 않습니다.

확인한 역할은 실제 `codex`/`claude` CLI를 실행하는 래퍼의 **모델 라우팅**입니다. 새 사용자 턴에서 선택하고 도구 루프의 모델은 유지하며, 하위 에이전트는 따로 관리합니다. CLI 인증을 전달하고 Jev 오류 시 fallback합니다. 프롬프트는 TypeSafe 라우팅 서비스에 전달되므로 비밀값을 작업 프롬프트에 넣지 않습니다.

설치본 확인에서 CLI의 ChatGPT 로그인과 키 설정의 존재가 확인됐어도 키 인증·라우팅 왕복·실제 업무 완료는 별도입니다. 원격 프로세스가 사용자 환경변수를 상속했는지도 확인해야 합니다. 키 값은 출력하거나 저장소에 기록하지 않습니다.

컨트롤타워의 발견·큐·작업폴더·진행률·검증·결과 전달은 실행기 책임입니다. 라우터 설치나 프로세스 실행을 이 전체 흐름의 완료로 표현하지 않습니다. 직접 Codex 경로와 Jev 경로를 동일 완료 조건에서 비교합니다.

## 상태 기록 계약

| 상태 | 필요한 증거 | 이 상태가 증명하지 않는 것 |
|---|---|---|
| 후보/문서 확인 | 공식 출처, 확인일, 지원 기능·제한 | 설치·실행 |
| 설치 확인 | 실제 경로와 버전 또는 패키지 메타데이터 | 현재 인증·기능 성공 |
| 현재 연결 | 해당 세션 도구 제공 또는 연결 점검 | 특정 API 호출·전체 작업 완료 |
| 기능 실행 검증 | 요청·응답/exit code와 검증 대상 | 다른 작업·다른 기기 성공 |
| 사용자 흐름 완료 | 실제 입력부터 최종 결과까지 필요한 검증 | 미실행 플랫폼·외부 환경 성공 |

기록에는 프로젝트, 작업, 환경, 확인 시각, 근거, 실제 경로, 검증/미검증을 포함합니다. 도구 목록에 존재하는 Context7은 이번 세션에서 **도구 제공 확인**이며 이 조사만으로 해당 프로젝트 API 질의 성공을 주장하지 않습니다. Playwright CLI·Vercel Skills·Ruff·PSScriptAnalyzer·FFmpeg는 여기서 **공식 문서 확인**이며 새 설치·실사용 검증 기록이 아닙니다.

새 AI 작업의 기본 위치는 최신 사용자 D드라이브 지시와 실제 관찰을 반영한 `D:\A_KJ\AI`입니다. 항목별 실제 경로, 공식 업데이터 예외, 이동 완료는 설치 등록부에서 별도로 확인합니다.

## 측정과 채택

- 동일한 완료 조건의 대표 작업을 선정합니다. 단독/소수 병렬, 직접 CLI/Jev 경로를 필요할 때 비교합니다.
- 완료 시간, 검증 성공, 재시도, 전체 에이전트의 사용량, 중복 명령, 모델/라우팅/fallback을 기록합니다.
- Codex `exec --json`은 JSONL 이벤트와 `turn.completed` usage를 제공합니다. 설치된 버전의 실제 형식을 확인해 수집합니다.
- input/cached input/output/reasoning을 구분합니다. 하위 작업 사용량을 합칠 때 부모 측 포함 여부를 확인해 중복 집계를 피합니다. 누락은 0으로 기록하지 않습니다.
- 토큰 수, API 과금, ChatGPT 구독 사용 한도는 같은 값이 아닙니다. 측정하지 않은 `% 절감`을 게시하지 않습니다.
- 비용·호환성·권한·작업 종류가 달라지면 재검토합니다. 과거 좋은 결과도 모든 프로젝트에 영구 고정하지 않습니다.
