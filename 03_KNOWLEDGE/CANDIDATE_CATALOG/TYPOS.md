# typos (`crate-ci/typos`)

확인일: 2026-09-17
상태: 후보 — 필요 프로젝트에 선택 적용

## 한줄 판단

소스코드·문서·설정 파일의 흔한 영문 오타를 빠르게 잡는 경량 CLI. 코드/문서 품질 검증 파이프라인에서 Ruff/actionlint와 겹치지 않는 철자 검사 계층으로 쓸 가치가 있다.

## 운용 분류

| 축 | 판단 |
|---|---|
| ① 현재 바로 쓸 수 있는지 | 예 — CLI 및 prebuilt release 제공 |
| ② 설치 없이 ChatGPT/연결 서비스로 사용 | 아니오 |
| ③ AI가 설치·설정 가능한지 | 가능. 환경 권한/UAC가 막히면 사용자 도움 가능 |
| ④ 핵심 기능 AI 단독 운용 | **AI 단독 가능** |
| ⑤ 사용자 1회 도움 | 기본적으로 없음. 시스템 설치 권한이 필요한 환경은 예외 |
| ⑥ 사용자 GUI 필요 | 없음 |
| ⑦ 주 사용자 | AI/사용자 둘 다, 특히 자동 검증용 |
| ⑧ 실제 설치/채택 | 후보. 설치됨으로 기록하지 않음 |
| ⑨ 설치·운영 부담 | 🟢 가벼움 |
| ⑩ Cloud/self-host | 로컬 CLI라 구분 불필요 |
| ⑪ 보안/권한/라이선스 | MIT OR Apache-2.0. 자동 수정 전 diff 확인 권장 |
| ⑫ 비용 | **무료/오픈소스**. 외부 API/클라우드 비용 없음 |

## 왜 후보인가

- 소스 코드, 주석, README, 설정 등에서 흔한 오타를 빠르게 검사한다.
- 프로젝트 고유 단어/식별자는 설정 파일에서 예외 처리할 수 있다.
- CI에 넣기 전에 로컬에서 `typos`로 검사할 수 있어 AI가 수정 후 스스로 검증하기 쉽다.
- Ruff는 Python lint/format, actionlint는 GitHub Actions 구조 검증이고 `typos`는 철자 오류 계층이라 역할이 다르다.

## 안전 운용

기본은 읽기 전용 검사부터 한다.

```text
typos
```

자동 수정 기능(`--write-changes`)은 바로 기본값으로 쓰지 않는다. 먼저 결과 확인 → 필요한 수정 적용 → `git diff` 확인 → 재검사 순서를 권장한다. 프로젝트 고유명·한글 혼합 문서·생성 파일은 false positive나 불필요한 스캔을 줄이도록 설정에서 제외한다.

GitHub Action으로 사용할 수도 있지만 third-party Action은 tag/SHA와 권한을 별도로 검토한다. 로컬 CLI만으로도 핵심 기능을 사용할 수 있으므로 Action 설치가 필수는 아니다.
