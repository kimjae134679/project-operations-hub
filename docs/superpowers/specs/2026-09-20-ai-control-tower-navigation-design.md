# AI Control Tower 내비게이션 및 Jev 창 분리 설계

## 목표

`Desktop.7z`의 `AA_01`·`AA_02` 분위기를 유지하면서 메인 창에 좌측 내비게이션을 복원하고, 작은 화면에서도 모든 기능을 스크롤로 확인할 수 있게 한다. 현재 메인 화면을 차지하는 Jev 입력 영역은 별도 창으로 분리한다.

## 범위

### 포함

- 고정 폭 좌측 내비게이션: 홈, 도구 상태, Jev 작업, 설치·복구
- 오른쪽 전체 콘텐츠를 감싸는 단일 세로 스크롤
- 요약 카드, 도구 상태 표, 실시간 콘솔, 설치·복구, 보안 안내가 잘리지 않는 레이아웃
- 별도 `JevControlWindow`
- 기존 프로젝트 경로, 작업 내용, 실행, 취소, 현재 상태 기능 유지
- Jev 작업 창을 중복 생성하지 않고 기존 창을 다시 활성화
- 현재 로컬 실행 정책과 OpenAI/ChatGPT 계정 사용 금지 유지

### 제외

- GPT Prompt Scheduler의 예약·지연·반복·이력 기능
- ChatGPT/GPT 연결, 브라우저 탭 연결, 대화 복구, 인수인계
- Codex 승인창 또는 Windows UAC의 자동 클릭·전면 자동 승인
- 새로운 외부 서비스나 API 연결

## 메인 창 구조

- 루트는 `224px | *` 2열 구조로 구성한다.
- 왼쪽 사이드바에는 앱 이름, 메뉴 버튼, 버전/보안 안내를 둔다.
- 오른쪽은 `Auto` 헤더와 `*` 본문으로 나눈다.
- 본문 전체를 하나의 `ScrollViewer`로 감싼다.
- 본문 순서는 요약 카드 → 도구 상태 → 실시간 작업 콘솔 → 설치 및 복구 → 보안 안내다.
- 요약 카드는 폭이 부족하면 다음 줄로 배치되도록 구성한다.
- 도구 표와 콘솔에는 최소 높이를 주되 고정 행 때문에 다른 영역이 사라지지 않게 한다.
- 사이드바 메뉴는 해당 영역으로 스크롤하거나 Jev 작업 창을 연다.

## Jev 작업 제어 창

- 새 WPF 창 `JevControlWindow`를 추가한다.
- 프로젝트 경로, 작업 내용, 정책 상태, 실행·취소 버튼, 현재 작업 요약을 표시한다.
- 기존 `MainViewModel`의 상태를 공유해 메인 창과 작업 창의 표시가 서로 어긋나지 않게 한다.
- 한 번 열린 창은 다시 만들지 않고 활성화한다.
- 사용자가 창을 닫아도 메인 관제탑과 상태 갱신은 계속 유지한다.
- 로컬 Jev 실행은 현재 정책상 비활성이므로 실행 버튼과 설명에 이유를 분명히 표시한다. 예약·GPT 관련 기능은 추가하지 않는다.

## 권한 정책

- 현재 Codex/시스템 권한 요청 방식을 유지한다.
- 앱이 외부 승인창을 감지해 자동으로 승인하지 않는다.
- 반복 승인 감소는 Codex가 제공하는 제한된 명령 접두어 승인 기능을 사용할 때만 적용한다.
- 삭제, 시스템 설정, 비밀값, 외부 전송은 자동 승인 대상으로 만들지 않는다.

## 오류 처리

- Jev 창을 여는 중 오류가 나면 메인 창에서 한국어 메시지를 표시한다.
- 스크롤 이동 대상이 아직 로드되지 않았으면 창 로드 후 이동한다.
- 기존 설치·제거·복구 예외 처리와 민감값 제거 규칙을 유지한다.

## 검증

- 기존 단위 테스트를 모두 유지한다.
- 메인 창과 Jev 창이 XAML 컴파일되는 Release 빌드를 수행한다.
- Jev 창 단일 인스턴스 동작과 공유 ViewModel 수명을 테스트 가능한 도우미로 분리한다.
- 작은 창 크기에서 모든 섹션이 단일 스크롤로 접근 가능한지 실제 실행 화면으로 확인한다.
- Jev 실행 버튼이 정책상 비활성이고 직접 실행 우회 테스트가 계속 통과하는지 확인한다.
- 최종 EXE를 기본 배포 경로와 설치 경로에 반영하고 GitHub 인수인계를 갱신한다.
