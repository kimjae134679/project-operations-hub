# 사용자 수동 로컬 조회 모드 — 0.9.2 읽기 전용 기능 기록

## 0.9.9 명시 PC 설치·복구와 두 원격 상태

- `--manual-control`의 **설치·복구**는 버튼을 직접 누르고 확인했을 때만 기존 검증된 ProjectBridge 설치기를 실행합니다. 진행 중인 PC 작업은 먼저 마무리합니다. 기기 ID·인증·설정·작업 기록·백업과 보호 권한은 유지하며, 시작·타이머·재연결은 설치 승인이 아닙니다. `--local-view`는 계속 설치와 명령 실행이 차단됩니다.
- **PC 연결 시작**은 기존 인증 API를 우선 사용합니다. API 주소가 없거나 연결이 끊겼을 때만 기존 `프로젝트연결.exe --resume --background`로 복구합니다. 인증 거부·잘못된 주소는 네이티브 실행으로 우회하지 않습니다. 자동 상태 갱신은 설치나 새 연결 실행을 하지 않습니다.
- PC 연결 화면에서 **ProjectBridge의 로컬 명령 통로 / GitHub 중계**와 **Desktop Commander의 Online / 인증 / 원격 호출 잔여량**을 따로 표시합니다. Commander Online이어도 잔여 0%면 원격 호출 가능 상태가 아닙니다. PC 명령의 기본 통로는 실제 인증된 ProjectBridge이며 Commander 잔여량 때문에 중단하지 않습니다. 양쪽이 확인되지 않으면 정상이라고 표시하지 않습니다.
- Commander 계정 잔여량은 로컬 사용 기록으로 추측하지 않습니다. 기존 앱 데이터의 `remote-commander-observation.json`에 보관한 커넥터 확인값·시각을 표시하며 5분이 지나면 **마지막 확인 / 현재 재확인 필요**로 구분합니다. 값이 없으면 미확인입니다. 로컬 자동 복구 감시의 최근 응답은 별도로 표시하며 클라우드 Online이나 잔여량의 증거로 쓰지 않습니다.
- 이번 소스 변경의 코드 검사와 실제 새 패키지 배포·설치 실행·사용자 화면 확인은 별도 단계입니다. 키보드·마우스 자동 조작 없이 검사하며 실제 화면은 사용자가 제공하는 캡처로 확인합니다.

새 실행 파일을 사용자가 직접 열 때 `AIControlTower.exe --local-view`로 기존 운영 창과 별도 조회 창을 사용할 수 있습니다. 읽기 전용 경계는 0.9.3 소스에도 유지됩니다. 아래 읽기 전용 경계와 최신 manual-control 배포 기록을 구분합니다.

- 기존 설정을 최대 256KiB·JSON 깊이 16으로 읽고 프로젝트/소통/등록 상태 파일 위치를 사용합니다. 설정을 저장하지 않습니다. 설정 파일이 없으면 D 관리 루트를 사용하며 읽기 실패는 보류로 표시합니다. C fallback 설치·새 설정 생성은 하지 않습니다.
- 기존 로컬 공지·확인 기록·소통 글/댓글·등록 작업/연속 실행 체크포인트·내부 문서를 읽습니다. GitHub 연결, 공지 전달/자료 수집, 외부 API 상태 확인은 하지 않습니다. 없는/잘못된 공지 자료를 연결 성공으로 표시하지 않습니다.
- 설정·테마 선택·사용자 읽음 위치는 저장하지 않습니다. 공유 작업의 `running/queued` 기록을 interrupted로 바꾸지 않습니다. 표시 시각·저장 상태는 현재 프로세스 생존이나 실제 완료 확인이 아닙니다.
- 프로그램/Jev/PC 명령·원격 켜기/끄기·설치/복구·자동 시작·공유는 비활성/보류이며 실행 handler도 차단합니다. 프로젝트 폴더와 외부 앱/브라우저를 대신 실행하지 않습니다. 텍스트 자료는 기존 내부 reader의 승인 경계와 민감 파일 차단을 따릅니다.
- 운영 앱과 별도 local-view mutex/event를 사용합니다. 중복 조회 실행은 기존 창에 활성화 신호를 보내지 않고 종료합니다. `--background`, 원격/검증 등 다른 모드와 혼합한 요청은 거부합니다.

## 0.9.3 배포·실행 · `--manual-control`

- `AIControlTower.exe --manual-control`은 local-view와 별도 모드입니다. 두 모드를 혼합하지 않습니다.
- 등록·인증된 PC 연결은 자동 유지하고 등록 소유 작업은 수동 실행합니다. Jev는 설치된 proxy와 기존 ChatGPT의 명시 `gpt-6.1-sol` 경로를 사용하며 유료 API fallback·자동 Astra를 차단합니다.
- X는 tray/background로 보내고 종료는 별도로 선택합니다. 기존 원격을 함께 끄지 않습니다.
- 설정·Git·설치·임의 복구·계정 권한을 자동 변경하는 허가가 아닙니다. Jev Enable을 강제로 저장하지 않으며 작업마다 근거를 재검증합니다. 모델/인증/설치 변경·24시간 만료 시 중지합니다.
- 0.9.3을 publish해 manual-control PID 16092로 실행했습니다. 상태 파일의 버전·tray·PC 연결을 확인했으며 live UI·실제 Jev 작업 검증은 하지 않았습니다. Jev 응답 `1`/native exit0/turn completed는 별도 tool call 없는 검사입니다.
- 소유한 0.9.2 조회앱(PID 376)만 정상 종료했고 원격 supervisor(PID 5996)·다른 기존 프로세스·C 설정을 보존했습니다. `START_LATEST_VIEW.cmd`는 `START_MANUAL_CONTROL.cmd`로 전달하며 기존 예약은 PAUSED입니다.

## 화면에서 이어 보기 · 공통 소스 UI

- 기본 화면은 첫 탭 **내 프로젝트**입니다. 다음 탭은 **프로젝트 작업**, **통합관리 진행**입니다. 작업 검색은 입력칸 안에 표시하며 상태 파일 등록은 접힌 **고급**에서 선택합니다. 화면의 **밝게 / 어둡게** 버튼은 현재 선택을 테두리로 표시합니다.
- 안내·기록 읽기의 **이전 문서 / 다음 문서**는 최대 24개 문서 위치와 읽기 상태만 창 메모리에 보관합니다. 본문을 history에 저장하지 않고 원래 승인 루트에서 다시 읽어 민감 자료 차단을 재검사합니다. **원래 화면으로**는 안내를 열었던 탭의 프로젝트/프로그램/검색/스크롤로 돌아갑니다. 이력·읽음·화면 비율은 디스크에 저장하지 않습니다.
- 도구·연결은 작업 기록이나 프로젝트의 명시적 실행도구 등록 근거가 있는 항목을 기본 표시합니다. **사용 근거 없는 등록 도구도 보기** 또는 제품 이름 검색으로 후보도 확인할 수 있습니다. 숨기는 것은 제거/설치 취소가 아니며 설치 확인은 실제 사용·성공·생존 확인이 아닙니다.
- 탭이 길면 가로 스크롤을 사용하며 선택한 탭의 테두리는 헤더 영역 안에 끝까지 보이도록 이동합니다. 내 프로젝트의 목록/프로그램/상세 사이 경계와 펼친 작업 기록의 경계를 끌어 크기를 조절할 수 있습니다. 창 크기나 프로그램 선택 변경 때문에 조절한 폭을 다시 초기화하지 않습니다.

소스/비GUI fixture 검증과 실제 새 실행 파일 배포·사용은 별도 단계입니다. 이번 배포는 소유한 이전 조회창만 정상 교체한 것이며 다른 기존 프로세스를 자동 업데이트한 것이 아닙니다. 기본 운영 모드의 외부 실행 기능과 로컬 조회 모드의 차단 정책은 그대로 유지합니다.

인수인계: 기본 운영 모드는 유지합니다. 에이전트가 기존 GUI를 닫거나 새 GUI를 실행하지 않고 빌드/fixture 검증만 마쳤다면 그 사실을 실제 사용자 실행과 구분해 기록해야 합니다. 자동화 재개나 운영 배포를 이 모드 구현으로 승인했다고 해석하지 않습니다.
