# 컨트롤타워 디자인 참고와 적용 기준

확인일: 2026-10-05. 이번 문서는 사용자의 후속 디자인 요청에 따라 **먹색 작업 공간과 소량의 선명한 라임 강조**를 제안합니다. 기존 밝은 화면의 검증과 이번 개편의 네이티브 검증은 구분합니다. 색상·배치는 구현자가 최종 화면에 맞춰 조정하며, 이 문서만으로 새 화면의 완료를 선언하지 않습니다.

## 먼저 보여줄 것

목적은 프로젝트와 폴더가 무엇인지 이해하고, 자료를 열거나 실제 작업을 시작하고, 관련 공지를 확인하는 것입니다. 기본 흐름은 **프로젝트 선택 → 기능별 자료·프로그램 → 해당 항목의 실제 행동 → 결과와 상세**입니다.

- 왼쪽 프로젝트 목록에는 한국어 이름·짧은 용도·폴더 역할을 둡니다. 확인한 6개 진입점은 유지하고, 관련된 이전·실험·복구 폴더를 독립 프로젝트처럼 늘리지 않습니다.
- 중앙에는 선택한 프로젝트 제목 하나와 기능별 항목을 보여줍니다. 큰 환영 문구·영문 배너·통계 카드·장식 그래프를 추가하지 않습니다.
- 오른쪽에는 선택 항목의 용도와 실제 행동을 둡니다. APK 위치 보기, 자료 보기, 제작 화면 열기, 등록 명령 실행을 서로 구분합니다.
- 공지는 독립 작업 공간으로 엽니다. 목록, 현재 본문, 본인의 적용 상태와 확인 행동을 구분합니다. 공지 수를 장식 숫자로 쓰거나 새 공지를 성공 토스트만으로 전달하지 않습니다.
- 경로·작업 로그·개발 점검·보관 자료는 필요할 때 펼칩니다. 검색하면 일치하는 그룹이 열려야 합니다. 목록 정리는 화면의 연결이며 실제 원본 이동·삭제가 아닙니다.

## 공지 화면과 자동 수집의 표현

공지 작업 공간에서는 **새 내용 확인**과 **내가 적용했는지 기록**을 서로 다른 행동으로 둡니다. 자동 수집이 성공했다고 다른 프로젝트 AI가 읽었거나 실제 작업에 적용했다고 표시하지 않습니다.

- 목록: 공지 제목, 현재 버전, 본인의 확인·적용 상태. 공지 ID·해시는 필요할 때 상세에서 확인합니다.
- 본문: 선택 공지의 원본 내용과 확인한 버전. 새 내용으로 바뀌면 과거 확인과 구분합니다.
- 고정 행동: 본인 식별자와 대상 프로젝트를 확인한 뒤 적용 완료·대기·해당 없음·막힘을 이유와 근거로 기록합니다. 단순히 본문을 띄웠다는 이유로 적용 완료를 기록하지 않습니다.
- 수집 상태: 마지막 성공 확인 시각, 확인한 원본·commit, 업데이트 유무, 실패 시 다음 행동을 보여줍니다. 실패를 빈 목록이나 최신 상태처럼 덮지 않습니다.
- 읽기와 공개 반영: 로컬 조회·로컬 receipt·GitHub에 공개된 receipt를 구분합니다. 자동 수집의 재시도나 앱 재실행이 같은 내용을 여러 확인 기록으로 부풀리지 않게 합니다.

구현·권한·자동 Git 수집의 실제 범위는 별도 코드 검토와 네이티브 검증으로 확정합니다. 이 문서는 자동 게시·다른 프로젝트 수정·별도 채팅의 자동 확인 권한을 부여하지 않습니다.

## 유지해야 할 실행과 검증 계약

프로젝트·프로그램 검색은 실제 항목의 동일성을 유지해야 합니다. 기본 행동은 명령이 있으면 등록 명령을 실행하고, 자료면 실제 파일·폴더를 엽니다. 용도 미확인 EXE에 실행 명령을 자동 생성하지 않습니다. 이미 응답하는 로컬 제작 화면은 재사용합니다. 공유 원격 연결을 재시작·종료하거나 원본 프로젝트를 이동하는 동작을 디자인 편의로 붙이지 않습니다.

1060×720에서 긴 한글 이름, 명령 선택, 대표 행동, 열기·중지 버튼을 확인합니다. 공지 본문이 길어도 목록과 기록 버튼이 밀려나지 않게 합니다. 프로젝트의 설명·자료 위치와 공지의 본문은 필요한 영역 안에서 스크롤하고 핵심 행동은 고정합니다. 펼친 작업 기록과 빈 검색 결과도 검사합니다.

기존 160ms 불투명도 전환은 Windows `SystemParameters.ClientAreaAnimation`과 사용자 움직임 줄이기를 존중합니다. 새 레이아웃에서도 스크롤·hover·선택 때문에 중요한 컨트롤이 이동하지 않아야 합니다. 기본 Windows 제목 표시줄과 창 이동·크기 조절을 유지합니다.

기존 검증은 [VERIFICATION-20261005.md](VERIFICATION-20261005.md)에 있습니다. 이번 dark/공지 개편의 검증은 실제 Windows WPF 빌드, 현재 데이터, 원본과 수집 상태, 본인 기록의 중복 방지, 작은 창 경계와 캡처로 별도 남깁니다. Linux에서 보는 웹 참고 화면·생성 이미지·HTML 모형은 이 WPF 앱의 실제 검증을 대신하지 않습니다. 게임 실기기·오디오북 GPU 제작·영상 다운로드·Jev 왕복 성공도 화면 개편의 성공으로 묶지 않습니다.

## 후속 구현의 소스 검토 상태
