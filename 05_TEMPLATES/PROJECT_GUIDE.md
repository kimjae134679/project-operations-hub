# 프로젝트 사용안내 작성 양식

실제 프로젝트 루트에 프로젝트_사용안내.md를 작성합니다. 기존에 같은 역할의 TXT/Markdown 안내가 충분하면 그것을 원본으로 유지하고 이 진입 파일에서 연결합니다. 예시를 실행 가능한 사실로 복사하지 않습니다.

## 첫 화면

프로젝트 이름과 하는 일을 쉬운 한국어로 설명합니다. 실제 작업 루트, 사용자가 먼저 눌러야 할 실행기/화면/목록, 누르면 무엇을 할 수 있는지 적습니다.

## 사용자 행동과 자료 지도

아래 역할마다 확인한 실제 위치와 구체적인 행동을 적습니다. 해당 자료가 없으면 없음/미연결/미확인으로 적습니다.

| 역할 | 적을 내용 |
|---|---|
| 실행·사용 시작점 | PC 앱, 웹 화면, 휴대폰 설치파일, 안내 목록을 구분. 실제 파일/주소와 무엇을 하는지. |
| 입력 | 사용자가 준비하는 텍스트·영상·주소·설정. 원본 보존 여부. |
| 결과 | 최신 완성 결과를 어디서 열고 듣고 보는지. 제작 중·검토 대기와 구분. |
| 비교·참조 | 사용자가 승인한 기준, 후보, 원본 자료, 별도 실험의 위치와 역할. |
| 이전·보관·복구 | 현재판과 이전판, 실험 사본, 복구본을 구별. |
| 진행·문제·복구 | 최신 상태/인수인계, 실패·검토 목록, 안전한 재개 안내. |
| 개발·환경 | 코드·모델·런타임·캐시 위치. 실행 중 작업과 사용자가 볼 결과를 구분. |
| 소통 | 실제 _통합소통 위치, 공지 확인과 본인 명령·실제 답변 기록 위치. |

음성 프로젝트는 최신 전체 음성, 새 제작 회차, 장면별 음성, 배역 비교, 선호 기준, 원본 표본·효과음/배경이 섞인 장면, 미승인 표본, 이전판까지 각 범주로 안내합니다. 모든 개별 WAV/MP3 파일을 복제·열거할 필요는 없지만 범주를 누락하지 않습니다. 소리 성격을 모르면 이름으로 추측하지 않습니다.

파일 링크는 같은 프로젝트의 상대 경로를 우선 사용하고 외부 위치는 실제 절대 경로를 씁니다. 폴더 링크에는 폴더 열기, 음성에는 듣기, 앱에는 실행, APK에는 휴대폰 설치파일이라는 설명을 붙입니다. 모든 링크의 실제 존재를 확인합니다.

필요한 경우 실제 화면 캡처·배치 그림을 기존 자료 또는 안내 이미지 폴더로 연결하고 무엇을 눌러야 하는지 설명합니다. 가독성에 도움이 되지 않는 장식 이미지를 추가하지 않습니다. 이미지에도 계정·비밀값·개인정보·소설 원문을 공개하지 않습니다.

## AI 시작·갱신

1. 최신 사용자 지시 → 이 프로젝트 로컬 안내 → 실제 README/AGENTS → 최신 인수인계 → 요청 관련 파일을 필요한 범위만 읽습니다.
2. 안내가 없거나 오래됐으면 실제 자료를 조사해 만들거나 갱신합니다. 안내만 보고 파일 존재·실행·외부 연결·품질 승인까지 추정하지 않습니다.
3. 경로·실행기·입력·결과·자료 범주·사용 방법이 바뀌면 같은 작업에서 안내를 갱신합니다.
4. 받은 명령·실제 답변·검증·남은 일은 task_exchange로 기록합니다. 이 사용 안내는 작업 기록의 복제 원본이 아닙니다.
5. 확인일·조사 근거와 이번에 검증한 범위/미검증을 적습니다. 다른 AI의 읽음·적용은 대필하지 않습니다.

자료를 보기 좋게 설명하려고 원본·모델·환경·실행기를 이동·삭제하지 않습니다. 원문·음원·영상·계정값·비공개 검토자료를 허브 공지에 복사하지 않습니다. 최신 실제 자료와 사용자 지시가 안내보다 우선합니다.
