# 프로젝트 사용 안내 작성 기준

실제 프로젝트 루트에 `00_사용안내.md` 또는 `00_사용안내.txt`를 작성합니다. 기존 `사용안내.md`, `PROJECT_GUIDE.md`, `00_START_HERE/사용안내.md`, `00_START_HERE/USER_GUIDE.md`가 있으면 그 안내를 유지해도 됩니다. 앱은 이 순서에서 처음 존재하는 파일을 읽습니다. 여러 안내를 중복 원본으로 만들지 마세요.

담당 AI가 실제 파일과 폴더를 확인하고 작성합니다. 안내는 사용자가 무엇을 열고 어디서 결과를 확인하는지 설명하는 진입점이며, AI도 재개할 때 이 안내와 현재 README/AGENTS·작업 기록을 먼저 읽습니다. 다른 담당자의 입력·음원·모델·보관 자료를 임의로 이동하지 않습니다.

다음 항목을 프로젝트에 맞게 짧고 쉽게 작성합니다. 비밀값과 소설 원문은 넣지 않습니다.

- 무엇을 만드는 프로젝트인지, 현재 작업 폴더와 실제 실행 진입점
- 결과를 듣거나 보는 위치와 여는 방법
- 비교 결과·다른 소리·캐릭터 표본·참고 영상 등 자료의 위치와 용도
- 입력·최신 결과·과거 결과·보관 자료를 구별하는 설명
- 현재 완료한 작업과 아직 준비만 끝난 작업, 확인한 날짜
- AI가 다음에 읽을 작업 기록과 `_통합소통` 위치

위치는 안내 파일 기준 상대 경로 또는 실제 절대 경로로 적고 존재·용도를 확인합니다. 파일 존재, 실행 성공, 품질 확인을 구분하며 미확인 위치를 추측으로 채우지 않습니다. 사용자가 제공한 실제 위치가 먼저입니다.

Markdown에서는 `[최신 음원 폴더](실제상대경로)`로 폴더·오디오·영상·이미지·문서를 연결할 수 있습니다. 앱은 실제 존재하는 지원 자료만 열며 실행 스크립트는 안내 안에서 자동 실행하지 않습니다. 실행 명령은 앱의 등록된 프로그램 기능으로 관리합니다. TXT는 원문을 읽는 데 쓰며 시각적 링크·이미지가 필요하면 Markdown을 사용합니다.

필요한 화면 설명은 `![듣기 화면](images/실제화면.png)`처럼 한 줄에 로컬 이미지를 넣습니다. 설명 없이 이미지만 나열하지 않습니다. 원본 자료의 위치를 유지하고 안내용 이미지와 재현 가능한 소스만 보관합니다.

예를 들어 무직전생 프로젝트에서는 '최신 MP3를 듣는 곳', '다른 목소리·연기 비교', '캐릭터 표본', '원본 영상', '텍스트와 대본', '현재·과거·보관 결과'를 각각 실제 위치와 함께 설명합니다. 이 문서의 예시 항목은 확인된 경로를 대신하지 않습니다.
